# 接入与执行

本说明使同一个技能包能在不同Agent、不同账户和不同工具环境使用。只配置当前任务需要的部分，不要求创建固定目录或指定文件名。

新增直播间或准备长期 Codex 会话时，按[简短接入](新直播间接入与双宿主会话.md#接入流程)由Agent自动定位账户、主计划及已存策略；用户不用整理技术交接，DSH 配置不作前置。本说明继续负责通用能力与写后回读，不另维护一套接入提示词。

## 1. 没有作者工作区也能使用

规则题只需技能包。离线分析只需用户给定报表和问题。已有策略文档时引用它；没有文档但本次用户明确了限制，可将这些条件用于本次分析，不要求用户先建立完整“工作区”。

需要保存账户信息或任务记录时，先按[工作区与资料准备](工作区与资料准备.md)定位现有文件，按需采用其中的Markdown模板。[上下文模板](../assets/account-context.template.json)是可选的机器可读任务输入；已有账户策略时以路径引用，不再复制一份长期阈值。Agent先填有来源的已知项，用户只补缺失事实和确认经营取舍。不要把某个账户的资料填写进技能包原模板。

工作区结构已存在时记录路径映射并沿用；缺资料的核对、索取和待补记录也按该说明处理。路径相对使用者的配置文件解析，技能内部资源相对本文件/技能根目录解析，不依赖终端当前目录。

模板中的null表示尚未提供，不表示0、不限额或已允许。实际授权以用户明确指令及可追溯授权记录为准；旧`mode/allow_*`字段不作为项目执行开关，不能只信资料或模板内自填字段。

## 2. 按任务确认最少信息

| 任务 | 必须辨认 | 暂时不需要 |
|---|---|---|
| 解释规则 | 产品、目标口径、具体问题；能从上下文确定就不再问 | 账户登录、真实账户ID、预算上限 |
| 给定数字计算 | 模式、同口径数字、时间段/变价分段 | 千川连接、完整经营策略 |
| 报表诊断 | 数据对象、日期/时区、汇总层级；用户要比较什么 | 实时写权限 |
| 制定具体参数 | 上述信息＋使用者目标、预算/出价范围及停止条件 | 没有必要的历史全库 |
| 实时操作 | 当前账户与对象、模式、相关真实状态、允许动作、约束及回读能力 | 与本动作无关的数据 |

没有利润信息时，只判断经营指标或用户目标是否达标，不宣称财务盈利。用户没给出价/预算边界时，可以先给候选方案并说明取舍；不要虚构账户默认线。

## 3. 工具按能力接入

工具名称不要求与作者环境相同。先读宿主实际暴露的工具说明和参数，建立当次映射，不靠示例猜字段。

| 所需能力 | 必要返回或用途 | 缺失时怎么做 |
|---|---|---|
| 身份/状态读取 | 账户、主计划或追投ID，投放模式、当前状态、读取时间 | 可做离线分析；不冒充当前状态 |
| 指标读取 | 时间窗口、消耗、订单、同口径GMV、数据新鲜度与缺项 | 定点补读或标注分析范围 |
| 任务/素材明细 | 任务归属、包内素材、预算周期、状态 | 不用包汇总代替单素材结论 |
| 操作历史 | 目标变更时间、出价/定向修改记录，必要时模式历史 | 保障次数或分段计算待核验 |
| 权限/能力检查 | 对应动作实际可用，目标参数范围与服务端限制 | 形成方案或人工步骤，不伪造调用 |
| 写入 | 对应对象、变量、值，明确受理/失败或请求标识 | 没有写能力就不称执行 |
| 回读/结果查询 | 当前值、对象状态和请求结果，能确认是否生效 | 保留结果未知，先查明再重试 |

直播读盘与调控使用宿主浏览器插件，按账户、主计划、房间和开播时间绑定。工具只执行模型指定的对象与参数。历史与素材数据查询另见[API功能图](../../../docs/逆向API功能图.md)。

### 浏览器故障处理

保留原对象和未决提交，按工具文档恢复同一浏览器连接。重新核账户、主计划、场次与页面状态。原提交未知只查原对象，不重发。无法核验时记录缺项和待办。

### 已有账户更新千川凭据

用户已要求更新本机项目凭据时，复用已登录同广告户的千川浏览器，不要求用户手动导出或粘贴Cookie；不重开户，不把凭据发给其他会话。索引入口为`tools/codex-qc-credential-refresh.mjs`，参数与调用见[凭据脚本](脚本索引.md#已有账户凭据更新)。

1. 核浏览器当前域、URL广告户与账户栏ID一致；绑定已有运行账户映射。只有用户授权导出时，才用当前宿主文档公开的CDP Cookie能力导出千川域到本机私有目录，不读取整个浏览器的其他网站凭据。
2. 导出文件只交本机工作台正式导入入口。脚本精确匹配已存在账户与发现的广告户，调用`onboarding import/select`；不调用开户`save`或覆盖账户策略。
3. 保存脱敏回执；通过浏览器按原账户、房间和开播核验。文件写入、账户保存、数据查询状态恢复分别标记；某个接口恢复不代表罗盘或所有操作已恢复。结果未知先查证，不自动重复保存。
4. 向需要接续的会话同步账户引用、核验结果和未完成项，不发送Cookie正文。不因更新凭据恢复已停止的直播或调度。

首次没有有效登录时仍由用户本人登录；验证码或当前工具不支持导出时，说明准确缺口，不退回用户手动导出文件的流程，也不猜登录状态。当前脚本只刷新已有千川账户，首次新增及罗盘同步须单独核验能力。千川与罗盘凭据分开，单户更新不覆盖其他账号。

## 4. 获授权动作的闭环

仅保护性停止的条件已经明确时，不额外等待一般优化性调价冷却。是否有回滚、如何回滚仍取当前工具及用户授权，不能保证每个动作都可撤销。

## 5. 持续任务与结束

持续运行需用户请求、宿主能力以及明确频率/停止条件三者齐全。已有读取纪律就沿用；没有时先给合适的具体方案，不自行套固定5分钟节奏。启动前确认没有同账户同场另一写入循环。

本项目直播间按固定经营标准连续接场；下播后停止旧场投控并待播，按[跨场接续与下播清理](新直播间接入与双宿主会话.md#跨场接续与下播清理)核实新场后继续。仅用户明确限制为单场或停止持续调控时结束调度。外部数据缺失不要求无限等待，可以结束一个清楚标注范围的分析任务。浏览器连接不可用时按工具文档恢复并核验；不改账户设置。
