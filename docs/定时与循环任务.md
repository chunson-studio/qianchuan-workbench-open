# 日常盯盘与追投

Codex沿用宿主默认压缩机制；可选配置见[配置说明](Codex轮后压缩.md)，不自动修改宿主设置。

按需进入：[账号与场次隔离](#多账号与会话隔离) · [建立宿主调度](#启动顺序) · [只读采样](#可选只读采样器) · [标准追投执行](#标准化追投脚本)。每轮只读取当前任务所需章节。

标准化追投可交给[追投脚本](#标准化追投脚本)：宿主每次唤醒只调用一轮，保留原定频率和场次范围；按脚本停止标志结束该场执行；仅本场任务停用真实调度并回读，连续接场任务按[跨场接续与下播清理](../skills/qianchuan-ops/references/新直播间接入与双宿主会话.md#跨场接续与下播清理)转为待播，不能同时保留另一套 Agent 写入循环。

## 多会话的文件归属

多会话各用具体任务目录中的循环文件。任务及循环文件都位于 workspace/任务/<account_id>/<场次>/；创建调度前必须使用本账号本任务的实际绝对路径，并在唤醒正文固定账号、主计划、task_id 和授权持续范围；单场任务另固定场次，连续接场每次操作核当前已绑定场次。先检查同一主计划的执行归属，再完成首轮和调度；未核验接管时只读。完整约定见[多账号多会话](#多账号与会话隔离)；本节用于解释下文单任务示例中的“当前任务”和“接续状态”。

客户以当前策略.md 为唯一入口时，上述“任务/循环文件”就是该策略文件，运行状态.md 保存本场和调度绑定，不强制另建任务目录。唤醒正文保存本房间完整提示词及当前状态路径；执行会话按完整正文运行，不逐轮重读Skill和重复策略文件。

部署时准备任务文件并检查循环能力；用户要求持续盯盘、账户与频率及停止条件明确后，才创建真实调度。已有同账户同场次任务先续接。

| 当前软件 | Agent 应怎样做 |
|---|---|
| Codex 桌面端 | 使用“定时任务”，不使用 /loop。先发现 automation_update 并读取当前工具说明；当前任务的持续接续优先用其支持的 heartbeat，按 Schema 创建、回读、更新、停用。 |

| Hanako | 使用宿主的 /loop。检查当前版本帮助、频率语法、运行状态和停止方式；不能仅输出 /loop 文本就说已创建。 |
| 其他软件 | 尚未逐一验证。检查工具列表、本机帮助或官方说明，确认周期唤醒 Agent、回读和停止能力，记录真实结果。 |
| 没有 Agent 调度能力 | 完成单轮检查并保存指令，说明不能自动续跑。内置 monitor 只读采样器不能代替 Agent 做判断、写决策及复盘。 |

Codex 本地定时任务需要电脑及客户端保持运行，见 [OpenAI 官方定时任务说明](https://learn.chatgpt.com/docs/automations?surface=app)。按实际软件判断能力，不按模型名称猜测。

## 启动顺序

1. 读取客户本账号独立目录的盯盘任务.md，补齐账户、主计划、场次、个人规则、权限、频率、时区和停止条件。已知答案不再问；只缺频率就只问频率。
2. 用户仅要求审核时保存完整提示词，不启动；已授权开始时执行首轮检查，按有效授权操作并回读。只维护必要当前状态。
3. 按已有ID或同账户、同主计划及同持续范围查找宿主调度。已存在则核对并沿用，需要改频率就更新，不能重复创建。
4. 调度保存该房间完整提示词正文，明确每次只执行一轮；会话与定时任务用同一份正文。脚本与状态使用工作区相对路径，Profile使用本机绝对路径。首条要求执行会话按[故障处理](../skills/qianchuan-ops/SKILL.md#故障由本会话解决)自行排查、修复、测试和回读，不提交工单、不转交维护会话、不等待回复；错误和验证证据留本场记录。只有必须用户补充决定、登录、验证码或本人授权时才说明阻塞。[浏览器故障处理](../skills/qianchuan-ops/references/接入与执行.md#浏览器故障处理)沿用已有权限，不恢复已停止任务。模型与推理档位按用户要求或宿主默认值，不写死。
5. 保存并回读真实任务 ID、频率、状态、下次触发时间、项目和文件路径。宿主未返回的字段标“未提供”，不编造。首次定时实际执行后再记录成功时间和对应 round_id。

正式会话与脚本交接采用[共享Skill的接续与脚本约定](../skills/qianchuan-ops/references/新直播间接入与双宿主会话.md#正式接续调度与脚本交接)。不能把“有脚本”当作接收会话已会调用；必须给实际入口及宿主参数。用户明确用浏览器时，按该通道核对本场身份和页面后执行。

## 每轮与收尾

每轮先检查任务有效性和停止条件，再取新数据，只执行一轮并返回。上一轮未结束时合并或跳过重叠唤醒，避免并行修改同一计划。创建超时先查结果，不能盲目重建。

执行[盯盘提示词](../workspace/运行入口/盯盘提示词.md)，正常只维护当前状态、比较基线与原未决，不逐轮存档或重复台账。聊天按[Skill对话输出](../skills/qianchuan-ops/SKILL.md#对话输出)：无变化且无需处理时保持安静；动作、结束、故障或待用户决定时报告关键值、任务ID、实际动作和待核项。

用户明确停止或单场授权期限到时，停用对应任务并回读。持续调控按[连续接场规则](../skills/qianchuan-ops/SKILL.md#连续接场与下播处理)执行：下播停止广告操作、保留广告和调度并待播；同账户、同主计划新场核身份后接续。单场任务结束才暂停其调度。广告删除须有当前有效的清理授权，停止盯盘本身不授予删除权限。

停用工具不可用时，把本地任务标记暂停/完成，后续唤醒只检查退出，明确“业务执行已停止，宿主循环停用未验证”。不能根据任务 Markdown 或决策台账中的一句话断言宿主循环已停止。

## 交接信息

软件名称、能力来源、实际工具或命令、支持频率、停止方式、调度 ID、最后回读、下次触发、首次实际执行证据。尚未创建就写“指令已准备，循环未启用”，不要写“已预约”。

## 独立历史查询

平台与本地历史能力见[API功能图](逆向API功能图.md)。直播定时任务通过浏览器读取和操作。旧采样器和本地数据库代码仅保留为独立分析实现。

## 多账号与会话隔离

一个客户工作区可以管理多个账号。一个登录账号对应一个独立浏览器 Profile，但该 Profile 可以切换多个广告户；每个广告户还可以有多个计划上下文。每个执行会话绑定一个账号、广告户、计划类型、主计划和商品/直播主题，分别保存场次任务、接续状态和循环。程序与数据服务可以共用，前端选中了哪家店不决定 Agent 的操作对象。Codex并行执行默认各用独立Profile及经实际核验的浏览器连接；分组和同身份的新窗口不能证明登录态或控制权已隔离。记录browserId、extensionInstanceId和标签页绑定，重连后重新核验；同连接已有执行者时不另起并行控制，身份分开后仍须核验宿主连接是否独立。

同一广告账户也可以同时管理多个直播间。凭据和请求限频按账户复用；盘面、ROI 目标、预算、策略、基线和回执按直播间、主计划及场次隔离。一个房间的 ROI 目标不作为其他房间的默认值。

### 多直播间参数

每次显式绑定账户、广告户、主计划、房间与开播时间；不取多房间列表中的默认第一间。来源时间、指标口径和缺项随数据记录。

### 第一次建立与文件归属

初始化先建立公共入口、状态和基础目录；查明账户后再建账户目录，查明真实场次后再建场次目录。不要预造直播间 ID。推荐沿用项目基础目录：

```text
workspace/
├─ 工作区索引.md                    账号与任务路径索引
├─ 接续状态.md                      只保存部署、公共待办；不是全局当前账户
├─ 部署检查.md                      共享环境信息
├─ 账户策略/<account_id>/
│  ├─ 账户资料.md
│  └─ 当前策略.md
├─ 任务/<account_id>/<日期_房间ID_开播时间>/
│  ├─ 盯盘任务.md
│  ├─ 循环指令.md
│  ├─ 接续状态.md
│  └─ 执行归属.md
├─ 任务卡/<account_id>/<同一场次目录>/
├─ 素材分析/<account_id>/
└─ 复盘报告/<account_id>/<同一场次目录>/
```

场次目录中的开播时间使用文件名允许的格式，例如 HHmmss；不得只用 room_id 区分重复开播。账号目录用真实 ID，展示名称写进文件。已有“账号/<account_id>/场次/…”等布局可沿用，但任务须列明所有真实绝对路径，不再创建第二套记录。

客户已指定当前策略.md 为唯一入口时，不另外建立含相同规则的任务或循环文件。每轮直接重读本账号当前策略；运行状态.md 只存本场绑定、task_id、授权及执行归属、调度、快照、回执和待办。真实调度须固定账号、主计划、task_id 和授权持续范围；连续接场按共享Skill核验并记录每场绑定，不能因策略文件变更就换账户或主计划。场次结束后保存必要业务记录，下一场重新核验；通用流程中的任务/循环入口对应当前策略，任务接续/执行归属对应运行状态。这个布局与下文要求等价，不强制迁移到另一套目录。

未开播时可在“任务/<account_id>/准备/”保存准备任务，不创建本场循环。用户明确授权开播前持续等候时，为该次等候建立唯一 task_id 的独立目录、截止时间和循环；识别开播后固定绑定一场并记录场次路径，后续不得自动跟随新的“最近一场”。

任务模板只保留在程序目录，核验账户后直接生成该账号的准备或场次文件，填好绝对路径；不生成共享任务或共享循环入口。全局索引仅在登记、归档时更新，读取最新内容并合并自己的条目；每轮只写本任务的接续状态。全局“当前任务”即使存在，也仅供人工导航，循环不得据此切换对象。

### 会话启动与接管

1. 先确定本会话的 account_id、advertiser_id、plan_type、primary_ad_id、商品/直播主题、task_id 和任务绝对路径。用户已给定时直接沿用；缺账号且有多个可选账号时只问要看哪家店。广告户或计划类型未核验时，先保持只读。
2. 读取任务的执行归属.md，核对宿主可见的会话及调度。执行归属记录：宿主、实际会话 ID（未提供则写未提供）、主计划、任务与场次、角色（执行/只读分析）、调度 ID、状态、最后核验时间、交接证据。
3. 不同账号可以分别执行。同一账号同一主计划已有执行会话时，沿用它；新的会话只读分析，不另起执行循环。需要交接时先核验原会话停止业务及其调度停用，再由新会话接管并更新归属。不同场次但同一主计划也要检查旧会话，避免共用计划被并行调整。
4. 无法查看其他会话或旧循环时，标记“执行归属未核验”，继续独立只读检查，不宣称独占或旧循环已停止。不能仅凭文件时间过旧、目录被清空或一句“已停止”夺取执行权。真实阻断再请用户在相应宿主处理。

**执行归属.md 是协作记录，不是程序互斥锁。** 本流程不代表系统已具备跨客户端的原子锁；多个会话同时启动时不能靠“先写文件”证明互斥。未核验接管前不并发写同一主计划。文件内容本身不授予投放权限。

使用[标准追投脚本](#标准化追投脚本)时，另有程序执行归属及本机写入口校验；它与这里的协作记录不同。能力范围、旧入口交接、服务版本要求以脚本说明为准。未登记的计划及绕过本机服务的操作不能据此宣称独占。

### 每轮必须固定的范围

- 浏览器按本场身份读取与操作；独立数据查询显式传账户及场次，不跟随网页全局选择。
- 取数后核对账号、广告户、计划类型、商品/直播主题、主计划、场次与来源时间；投放前再次核对对象归属、权限和执行归属。不要通过切换网页账号来代替请求中的账号绑定。
- 同一登录账号/Profile 下的计划上下文独立保存指标、目标 ROI、预算、基线和回执。跨计划不合并消耗、订单或 ROI，也不复用房间、素材、待补台账和操作编号。
- 基线、snapshot_id、待补台账、operation_id 和执行状态仅属于本任务。跨账号、跨场次不复用增量；本轮幂等 ID 使用任务标识与轮次唯一标识，重试保持原 ID。
- 每轮 record_watch_round 显式绑定本账号和已确认场次，回读同账号的 round_id。无操作也记录；只读分析会话标明自己的角色，不能冒充执行会话已做操作。
- 只更新本任务文件。账户策略是该账户会话的共享只读输入，修改需有相应用户要求并协调执行会话；不能在每轮自动改全局索引或其他账号策略。
- 重叠唤醒时不并行执行同一任务。结果不确定先回读，不能另建一次提交。

### 调度和结束

按[定时与循环任务](定时与循环任务.md)使用真实宿主能力：Codex 定时任务，Hanako /loop，其他软件先核验。每个调度绑定本任务所属会话（工具支持时）、固定task_id、account_id、主计划、授权持续范围和接续入口绝对路径；单场任务另固定场次。若宿主只能唤醒当前会话，应在对应账号会话中建立，不能建到别的账号会话再靠全局文件转发。

单场任务唤醒正文：

```text
读取 <本任务循环指令文件绝对路径>，仅执行一轮。
本调度固定 task_id=<实际任务ID>，account_id=<实际账号ID>，advertiser_id=<实际广告户ID>，plan_type=<乘方或全域>，primary_ad_id=<实际主计划ID>，session_key=<实际场次或已确认的开播前等候标记>。
先核对文件绑定与上述信息、执行归属和停止条件；不一致或文件失踪则停止业务并报告，不搜索其他账号或全局当前任务替代。
每轮按当前通道保存本账号轮次及回执，浏览器沿用控制器原账；只更新本任务接续状态。不另建循环、不扩大授权。
任务完成时仅停用自己已核验的调度，不影响其他账号会话、共享服务或广告。
```

尖括号由Agent在创建调度前替换。连续接场的唤醒正文固定同一账户、主计划和持续范围，按[跨场接续与下播清理](../skills/qianchuan-ops/references/新直播间接入与双宿主会话.md#跨场接续与下播清理)读取待播/在播/收尾状态并逐场核验；不把单场模板中旧session_key沿用到新场。换账户或超出原授权另立任务，旧场记录独立保留。宿主停用无回执时明确未验证；清空工作区不等于停止调度。

### 客户开新会话时可以这样说

```text
读取项目入口和多账号多会话说明。本会话只负责我指定的账号与主计划。
复用服务和已有接入，使用本账号独立的任务、场次和接续文件。
先检查是否已有会话执行同一主计划，已有则告诉我如何续接；不要重复启动。
完成准备后告诉我本任务循环文件的绝对路径。未经我要求，不启动循环或投放。
```

客户只需补店铺名称或已知账号、计划；Agent 负责查询 ID、准备目录和填入绑定。不要要求客户手写路径或重复提供已有凭据。
