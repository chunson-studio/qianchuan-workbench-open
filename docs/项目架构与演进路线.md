# 千川工作台：项目架构与演进路线

按需进入：[系统概览](#系统概览) · [通道选择](#通道选择与兜底) · [当前能力](#当前已完成正在稳定和未实现) · [代码导航与索引](#代码导航与索引维护)。

本项目面向多账号、多直播间运营，同一广告户下的多个直播间也分别维护 ROI 目标和策略。当前只推进 Codex，通过浏览器完成日常读盘和调控，API用于独立历史查询与复盘；通道选择及切换规则统一维护在[通道选择与兜底](#通道选择与兜底)。DSH 暂不启用或配置，旧凭据与操作证据保留，不作 Codex 前置。

本文记录当前代码事实、已经确定的架构决策和后续开发边界。账户、Cookie、浏览器 Profile、客户策略和运行回执不写入通用包，也不写入本文。

## 系统概览

模块职责和调用关系统一维护在[极简项目地图](README.md#极简项目地图)。按源码锚点核验，不以图上连线代替实盘证据。

### 从目标到回执

你提出目标 → Codex 读取当前 Skill 与账户策略 → 通过浏览器取新数据 → 判断本轮动作 → 调用已验证的浏览器脚本 → 千川受理 → 回读实际结果 → 本机保存回执。

工作台网页用于账号管理与多账号已保存记录总览；千川调控页与罗盘大屏是浏览器投控的数据和操作入口。Codex 使用当前 Skill 作判断，脚本负责已验证的页面动作、本地计算与留底。逆向API和本地HTTP数据层保留为独立查询实现。最终花钱、投广告的是千川平台。

罗盘主要提供在线人数、进入与离开、成交变化等经营数据；千川提供广告消耗、追投任务和广告操作。罗盘数据快，也不能替代千川的广告状态与消耗口径。

| 组成 | 职责 | 详细说明 |
|---|---|---|
| Agent、Skill 与客户策略 | 按用户目标判断本轮动作；策略和案例本身不授予权限 | [知识入口](../AGENT_KNOWLEDGE.md)、[运行边界](agent-contracts/portable-runtime-policy.md) |
| 宿主调度 | 按已确认的频率唤醒对应会话，每次执行一轮 | [定时与循环任务](定时与循环任务.md) |
| 网页与HTTP数据服务 | 共用本机服务，提供账户管理、数据、操作和记录 | [API功能图](逆向API功能图.md) |
| API 与浏览器通道 | 读取平台数据、提交动作，按动作核验能力与结果 | [浏览器追投工具](浏览器追投工具.md)、[浏览器追投验收](浏览器追投工具.md#能力验收与待办) |
| 本地资料和回执 | 保存登录态、客户策略、原始证据和操作结果 | [文档目录](README.md#项目目录怎么分) |
| 插件、测试、索引与发布清单 | 支持安装、开发和交付；不代表广告效果或商业收费能力 | [内测交付](内测交付.md)、[商业化交付规划](内测交付.md#商业化规划) |

账户下面可有多个主计划，主计划下面可有多条追投任务，直播房间又有不同场次。操作绑定“账户 → 主计划 → 追投任务 → 房间与开播时间（适用时）”。商品卡没有直播场次的动作不能硬套直播规则，平台能力仍按实际对象核验。

### 预算修改示例

1. Agent 明确账户、主计划与任务 ID，读取当前预算和状态。
3. 本机服务核对实际旧值、范围、执行归属与调参额度。超过普通比例的增额仍须满足现有具体授权。
4. 默认走 API；明确选择 `execution_channel=browser` 才通过浏览器表单提交。预演仅核对和填写后取消。
5. 提交后读取同一任务实际预算。只有回读一致、回执成功保存，才报告“已确认”。
6. 若提交后断线，报告“结果未知”，沿原请求编号查证，不换通道重新提交。

时间参数使用秒：6 小时为 21600 秒，增加半小时为 1800 秒。修改总时长还要核对实际旧时长；不能用已经运行多久替代任务总时长。

### 三种浏览器方式

多直播间的原生并发通道按[独立会话与验收入口](../skills/qianchuan-ops/references/脚本索引.md#原生playwright独立会话与并发验收)接入。通道切换须分别验证对应账户和动作，不因测试页通过而改写现有调度；模型继续读取原始数据并决定经营动作。

| 方式 | 在哪里运行 | 是否是同一套脚本 |
| --- | --- | --- |
| Codex CUA | Codex 的浏览器工具运行时 | CUA 专用对象不能直接放进 Node |
| dsh 宿主浏览器 | DeepSeek harness 的浏览器插件 | 登录态与动作证据独立 |
| Node + Playwright / CDP | 本机固定脚本，连接明确登记的浏览器 | 按浏览器工具文档独立接入 |

三者都能定位按钮与页面文字，但对象、连接和登录资料不同。跨通道可以复用流程思路，不能冒充对方的实测证据。标准 Playwright 通道可供不同宿主按工具契约调用，实际接入状态见[浏览器追投验收](浏览器追投工具.md#能力验收与待办)。

普通程序可以承担连续点击、条件等待、回读和记录，Agent 取得精简结果。Playwright 本身不调用语言模型；减少返回字节不等于确定节省多少 Token 或费用。输出和实测方法统一见[Token 优化 SOP](逆向API功能图.md)。

隔离测试、真实平台受理、写后确认和投放效果分别报告。能力的精确验收状态只维护在对应验收正文，不从系统图推断功能已通过实机验证。

## 地图与本机摘要维护

地图只维护[极简项目地图](README.md#极简项目地图)，生成与漂移检查见[脚本索引](../skills/qianchuan-ops/references/脚本索引.md#极简项目地图维护)。旧大图、模板和导出链路已由极简入口替代，不再维护重复架构正文。

工作台只有账号管理、多账号总览两个入口，旧看盘、决策和复盘链接返回总览。总览按账号显示紧凑卡片，默认收起、一次展开一个，支持搜索账号或直播间；收起显示最近场次的消耗、原生ROI和数据新旧，展开显示该账号各主计划最近场次的经营数据及更新时间。页面不展示历史轮次、逐项回执或历史场次列表；底层执行状态继续用于防重复提交和异常恢复，主流程由 Codex 的已登录浏览器完成。

`GET /api/workbench-snapshot`只读统一控制器已有`runtime_root/codex-control/<账户与主计划哈希>/state.json`，不写原账、不持锁、不请求千川或罗盘。默认根目录为项目`private-runtime`及`work/browser-actions`；自定义运行目录由服务环境变量`QC_CONTROL_RUNTIME_ROOTS`指定，按宿主路径分隔符分隔。只设置当前控制器的实际根目录，不递归扫描历史、冻结源码或测试目录。

网页每30秒读取本机文件；按广告户和已登记账户唯一匹配，再按主计划、房间及开播时间隔离。网站罗盘默认关闭：`v4/index.html`的`data-website-compass="off"`由`shared.js`统一控制罗盘入口、在线人数和罗盘API请求；原代码保留，显式改为`on`可恢复。关闭时新旧判断只取当前读盘及财务时间，不依赖罗盘时间；采集超过5分钟标记历史，缺失、未来时间、同场冲突不冒充当前数据。财务保留原生全域/乘方口径；当前追投仅在完整池及成员变更可核时显示。各账号罗盘Cookie、Codex浏览器及独立API查询不受网站开关影响；缺记录不补采，保存时间不当平台更新时间。

网页打开、刷新与普通切页只读本机。账户管理中用户显式点击身份/计划核验仍可能访问平台；API仅用于独立历史查询与复盘。控制器已经保存的轮次无需再写一份前端台账；旧独立脚本和 MCP 历史账本没有合并接入，不能把本次只读投影称为跨通道去重或统一执行状态。

## 已确定的架构决策

## 产品定位与兼容策略

Codex 是当前主要使用和优先打磨的投放宿主。接入与维护围绕本场浏览器流程、最新 Skill、已验证脚本和独立运行记录开展。

当前接入只使用 Codex 及其所需接口：

| 客户方式 | 使用入口 | 能力范围 |
| --- | --- | --- |
| 使用 Codex | Codex CUA + 当前 Skill + 本场脚本 | 浏览器读取、判断、调控、回读与本机记录；当前默认方式 |
| Codex 浏览器故障 | 原浏览器连接恢复 | 核对原对象、页面与未决提交 |
| 不使用 Agent | 本地工作台 + HTTP API/脚本 | 已有接口能力可独立使用；浏览器操作需要已验收的本地适配器 |

各入口共享账户和场次绑定规则。Skill 文件同步、数据查询接通和宿主浏览器动作验收分别确认，不能据其中一项推断其他项。

产品包不捆绑个人 Codex 账号、会员凭据或客户 Cookie。商业化和脱离 Codex 的适配属于后续工作，不能改变当前接续任务的宿主或通道。

## 通道选择与兜底

直播间通过宿主浏览器插件读取原始页面、判断和执行操作。对象绑定账户、主计划、房间及开播时间。写后按原ID核验；结果未知先查原对象，不重发。

浏览器故障按工具文档恢复原连接，核验页面状态后继续。无法核验时保留待办。

API与本地历史数据用于独立查询、复盘和素材研究，见[API功能图](逆向API功能图.md)。旧千川MCP工具与策略执行入口已移除，数据工具重新按功能设计。

### 自动恢复范围与后续方案

独立Node扩展后台已专项验证单Profile的完整池读取、整页刷新恢复及连接子进程退出后接续；多账户启动隔离已有离线检查。具体入口和实际验证范围见[扩展后台索引](../skills/qianchuan-ops/references/脚本索引.md#微软playwright扩展接入与查询对照2026-10-15)。这些结果不表示下述完整经营自动恢复方案全部部署或全部通过。

2026-10-09用户要求多直播间全自动工作，并在脚本、浏览器接管或冲突影响业务时自动恢复。目标是检测并隔离单房间故障、恢复可执行业务；不承诺任何故障瞬时恢复。取消每轮执行用时上限不等于取消故障检测：检测依据连接健康、进程存活和进度心跳，持续无进展窗口由实际基线确定，不用统一短超时直接判死。

```text
模型给出本场策略 → 房间独立执行器 → 本房间专用浏览器身份
                         ↑
独立恢复服务 → 检测故障 → 隔离旧执行者 → 分级恢复 → 核本场身份与数据 → 接续
```

| 故障 | 恢复动作 | 边界 |
| --- | --- | --- |
| 组合脚本/选择器失败，浏览器仍通 | 已验证独立动作或本场直接浏览器备用 | 同一浏览器通道的手动点击不能解决通道本身断线 |
| 标签句柄失效 | 按Profile/扩展实例与业务ID重新发现并绑定 | 不复用短browserId猜身份，不抢别场标签 |
| 当前CUA脚本内核失效 | 由原宿主重置当前CUA环境，重新初始化和绑定 | 重置不关闭浏览器，也不撤回已发出的请求；不能清空未知后重发 |
| 本场中断锁 | 确认原调用结束，再核owner、token/revision或采集文件指纹，调用既有恢复入口 | 持久owner active不等于调用在途；仅锁龄不能证明可抢锁 |
| 跨会话真实占用 | 由统一执行归属协调释放、交接；每房间只一个写入者 | 不能让几个模型互相强抢，也不停止其他正常直播间 |
| 扩展/浏览器连接断开 | 重连原身份；仍失败时保留原对象与待办 | 按原浏览器通道恢复，不重发原未知；重启浏览器只在专用进程可隔离时实施 |
| 模型不响应 | 独立执行器继续本场已确认的确定性规则 | 新鲜数据、授权和单笔防重仍需满足；新策略等待模型 |

最小建设范围：一个独立恢复服务、每房间一个执行单元，复用现有浏览器动作、公式及当前状态。执行器向恢复服务报告当前步骤、进度和连接状态；恢复服务只有确认旧执行者停用后才交接。每次交接生成新的执行代号，所有提交在统一出口核代号，旧执行者醒来不能再派发动作；已经发往平台的请求仍可能完成，保留原请求并跳过重复操作。每房间只维护当前健康/恢复状态，不新增逐轮截图或冗余文档。

当前已核代码边界：`tools/codex-qc-control-state.mjs`使用独占文件锁并在finally释放，没有独立的心跳监控、执行代号撤销或进程监督；`tools/codex-qc-interrupted-lock-recovery.mjs`已有本人中断锁恢复，但需要宿主提供真实中断依据。当前可用CUA重置工具属于调用会话，未核实独立服务可远程重启任意Codex会话的接口。落地前须先验证可独立运行的浏览器执行通道，再接监督与接管；本次方案没有启用新守护进程或切换任何实盘通道。

验收必须注入脚本错误、内核退出、锁残留、扩展断连、错误标签、模型无响应和原提交未知，证明只恢复受影响房间、旧执行者不能继续写、不重复提交、其他房间继续，记录实际恢复时间。登录过期、验证码、平台不可用或全机断网不能靠重置内核保证恢复；必要时通知用户，仍可处理的独立房间继续。

官方桌面调度也依赖本机开机、桌面应用运行及项目可用，不能把会话定时唤醒当作操作系统级恢复服务。参见[官方定时任务文档](https://learn.chatgpt.com/docs/automations?surface=app)。

## 当前系统结构

调用关系见[极简地图](README.md#极简项目地图)，本节只补充模块职责和约束。浏览器执行与 HTTP 分支各自核验执行归属、未知结果及回执；网页通过本机服务只读浏览器已保存的摘要。

### 1. 本地服务层

`server-app/` 是本地 Node.js 服务。它提供 HTTP 路由、账户接入、数据读取、直播大屏、追投任务、决策台账、操作日志、缓存和回执处理。

当前运行时事实：

- Node.js 要求 `>=22.5.0`；
- 素材与直播历史库使用 `node:sqlite`，同时保留 JSON、JSONL、快照和报表文件；
- HTTP 服务使用 Node.js 内置模块和项目自己的路由层；
- 前端是静态 HTML、CSS、原生 JavaScript、Service Worker 和 SVG 资源；
- 服务端不持有浏览器/CDP 生命周期，浏览器由外部宿主连接；
- 启动检查使用 QC_DISABLE_BACKGROUND=1 避免隐式后台采集；测试注入模拟上游，不靠旧 QC_TRIAL_READ_ONLY 标志隔离真实请求；
- 配置、Cookie 和运行数据由 `QC_RUNTIME_CONFIG_ROOT`、`QC_RUNTIME_DATA_ROOT` 等运行时路径决定，不能从发布包推断客户数据位置。

### 2. 浏览器读取层

日常浏览器投控先使用本场交接的完整入口；罗盘专业版、两池读取、本地计算与保存的分工见[共享 Skill 的浏览器流程](../skills/qianchuan-ops/references/新直播间接入与双宿主会话.md#先查现成脚本再操作)。通用读取入口 `tools/codex-qc-read-workflow.mjs` 及底层采集器 `tools/codex-qc-read-once.cua.js` 继续保留，覆盖范围按当前脚本核验。读取包含：

1. 使用指定的浏览器标签和账户绑定；
2. 刷新页面；
3. 核验页面 URL、账户、广告户、主计划和日期；
4. 等待页面身份和表格加载完成；
5. 读取原始表头、单元格、任务行和页面更新时间；
6. 按表头清洗指标，不按固定列号猜字段；
7. 保存原始采集、规范化结果、隔离账本和 Markdown 回执；
8. 对已核验动作立即写入按钮库或动作登记，并保存证据路径。

默认Codex CUA通道负责连接浏览器、获取可访问性树和执行刷新。专项独立Playwright及扩展通道由Node后台持有已授权浏览器连接；数据处理模块继续在本地处理JSON/SQLite。各通道的身份、凭据、生命周期与实测范围分别核验，不因Node进程存活推定经营页面或广告动作可用。

### 3. 规则与执行层

Codex 读取当前 Skill 与本账户策略作经营判断，调用当前通道已验证的动作脚本。清洗、同场差分、实际消耗速度、反馈队列与轮次保存交给本地模块；完整入口及验证范围按本场交接和[浏览器按钮库](浏览器按钮库.md)核对。

持续工作由宿主调度唤醒，每次只完成一轮，不在脚本内创建无限循环。浏览器、接口和本机状态文件各自记录真实结果，不把生成动作清单当作平台受理。

### 4. 保留的 API 能力

现有API代码保留账户、历史、素材、追投与平台写入实现。数据接口按需用于历史查询和复盘；暂停、恢复及预算修改已按用户明确范围进行批量专项验收，尚未迁移日常调度或注册MCP写工具，其他写入仍保留研究。接口清单与实际验证范围见[API功能图](逆向API功能图.md)。

接口请求通过本机账户配置、显式参数和当前返回对象核对账户、广告户、计划及场次。字段缺失、数据过期和分页不完整时保留质量状态。执行通道遵循[通道选择与兜底](#通道选择与兜底)，两条通道都遵守[运行边界](agent-contracts/portable-runtime-policy.md)。

## 账户与浏览器 Profile 模型

账户与直播间绑定规则见[多账号多会话](定时与循环任务.md#多账号与会话隔离)。使用浏览器时，每个登录账号使用独立浏览器 Profile；一个登录账号下可以登记多个广告户，每个广告户可以有多个直播间和计划上下文。下面是浏览器绑定结构示意，不是 API 的启动前置条件。实际凭据只存在本机运行目录，不提交到仓库：

```json
{
  "account_id": "千川账户标识",
  "advertisers": [
    {
      "advertiser_id": "平台广告户标识",
      "primary_ad_ids": ["当前明确绑定的主计划"]
    }
  ],
  "plan_contexts": [
    {
      "primary_ad_id": "当前明确绑定的主计划",
      "plan_type": "乘方 | 全域",
      "product_scope": "页面核验后的商品或直播主题",
      "aweme_id": "页面核验后的抖音号或主播标识",
      "platform_target_roi": null,
      "roi_metric": "页面实际可读的指标名称"
    }
  ],
  "browser_profile": "本机独立浏览器Profile名称或路径",
  "browser_adapter": "codex-cua | playwright-cdp | extension-bridge",
  "allowed_actions": ["read"],
  "status": "active"
}
```

`advertisers.primary_ad_ids` 是浏览器登记中的计划绑定；本机 `private-runtime/plan-contexts.json` 的 `plan_contexts` 保存业务核对所需的计划类型、商品、抖音号和页面目标。登记资料还须与本轮接口或页面对象核对；浏览器操作同时核对当前页面身份。未知字段保持未知，不能用计划名称或浏览器当前选项推断。这里的目标 ROI 是平台设置值，不自动替代本轮观测指标，也不自动成为房间策略中的淘汰或扩量阈值。

### 当前已校正的计划上下文

下面两条是已有的页面身份资料，用于后续浏览器核对和测试范围登记。登记文件中的广告户映射沿用已有本机配置；这些记录不能证明当前页面身份、Profile 和直播场次，也不授予写入权限。使用浏览器时，仍需在页面上核对登录账号、广告户、计划类型、主计划、直播场次和日期。

每条计划都必须建立独立的 `plan_context`、场次、指标快照、基线、执行归属和回执。两条计划的消耗、订单、ROI、预算、任务数量和动作结果不能汇总后再判断，也不能把一条计划的目标 ROI、直播间或追投任务带到另一条计划。计划类型（乘方或全域）以本轮接口或页面证据核验；当前资料未记录广告户归属时，运行时必须先补齐并核验该字段。

启动浏览器读取或写入前必须同时核对：

- 当前浏览器 Profile 是否与登录账号映射一致；
- 页面右上角当前登录账号是否正确；
- 页面显示的广告户是否与本轮请求绑定一致；
- 页面显示的计划类型、商品/直播主题和主计划是否与本次任务绑定一致；
- 主计划、场次和日期是否属于本次任务；
- 是否存在其他会话对同一主计划的执行归属；
- 当前动作是否在账户策略和授权范围内。

Profile 不等于授权。登录状态只证明浏览器可以访问页面，不能自动授予广告写入权限。切换广告户或计划后必须重新核对页面身份、广告户、计划类型、商品和主计划；不能把登录账号名直接当成广告户。多个登录账号并行时使用多个独立浏览器实例或 Profile，不使用一个 Profile 在多个登录账号间来回切换。

当前只读工作流已支持通过本机私有登记文件做严格的“登录账号 → Chrome 扩展实例 → Profile → 广告户 → 主计划”校验，登记文件位于 `private-runtime/`，不进入发布包；运行时浏览器 ID 只作为本轮证据，不写回登记。正式启动器尚未强制所有旧入口都使用该校验，旧浏览器辅助代码仍可能使用单实例 Cookie 或临时 Playwright context，因此独立运行时接入完成前，不能把文档中的目标配置当作所有入口都已隔离。

## 浏览器适配器设计

共享浏览器流程与宿主适配层分开。Codex CUA 专用对象保留在对应适配层；DSH 和本地 Playwright/CDP 适配须独立验证。通用适配器至少提供以下能力：

```text
connect(profile) -> session
current_url() -> url
reload() -> void
read_accessibility_tree() -> tree
read_dom_table(table_hint) -> raw_table
click(control_id) -> result
fill(control_id, value) -> result
confirm_write() -> result
close() -> void
```

现有代码提供 `codex-cua` 和本地 `playwright-cdp` 入口；各自的登录态、绑定与实机证据独立验收，见[浏览器读取与建议](浏览器追投工具.md#浏览器读取与建议)。Codex 内置浏览器不承担多账号 Profile 隔离。适配方向包括：

1. `playwright-cdp`：本机独立运行的 Playwright/Chromium，适合脱离 Codex 的客户运行包；
2. `extension-bridge`：连接用户已登录的 Chrome Profile，适合复用真实浏览器会话；
3. `codex-cua`：继续作为开发、演示和人工可见操作入口。

各适配器接入时必须返回同一种原始采集契约，不能各自发明指标名称。浏览器动作的按钮登记与组合流程登记分开维护，按钮成功验证一次就立即写入[浏览器按钮库](浏览器按钮库.md)。

## 浏览器数据契约与清洗

原始页面数据和规范化指标必须分层保存。原始层保留页面 URL、绑定信息、更新时间、表头、单元格原文、截图或 AX 证据引用；规范化层保留字段值、单位、状态和来源列名。

指标状态至少区分：

- `available`：页面明确给出值；
- `missing`：页面没有该列或该行没有值；
- `unknown`：读取失败或口径不能确认；
- `not_applicable`：该计划类型不适用。

空白和 `-` 不等于零。支付 ROI、净成交 ROI、综合营销 ROI、普通消耗、综合成本、支付订单和净成交订单分别保存。计划页的“综合营销 ROI 目标”是设置字段，和追投列表或大屏的观测 ROI 分开保存。全域页面没有观测用的综合营销 ROI 时，不能用支付 ROI 或净成交 ROI 自动填充；乘方页面显示的营销 ROI 也只能按当前页面的实际列读取。两种计划的观测指标不能跨计划代填。

刷新时间、采集时间和页面统计更新时间分别保存。刷新后仍可能存在平台统计延迟，系统只能报告“页面当前显示值”和采集时间，不能保证平台后台已经完成结算。

## 运行模式

| 方式 | 浏览器 | API | 适用场景 |
| --- | --- | --- | --- |
| Codex 浏览器投控 | Codex CUA | 按需辅助，广告通道依照当前选择 | 当前默认的日常读盘、追投、回读与复盘 |
| DSH 等其他宿主 | 该宿主已核验浏览器 | 按明确任务使用 | 保留兼容；切换前完成执行交接 |
| API 运行 | 接口任务不要求浏览器 | 已有接口与本机服务 | 用户明确选择或独立数据任务 |
| 本地 Playwright/CDP | 已绑定的本机 Profile | 按独立浏览器入口调用 | 独立适配按实际能力验收 |
| 离线复盘 | 不需要 | 本地 SQLite/报表 | 历史分析、规则验证、回测，不写广告 |

各方式的 Cookie、Profile 和业务记录留在本机。能力是否可用由当前通道的验证结果决定，表中的使用定位不代表新通道已经接通。

## JEV 的后续接入边界

JEV 只有在以下信息确认后才进入技术评估：模型准确名称、官方或可信接口、计费方式、速率限制、数据是否出境、是否支持本地部署、服务条款和输出格式。

接入时只能作为“判断建议器”，不能直接获得浏览器控制权或广告写权限。推荐链路为：

```text
浏览器或接口数据/本地账本 -> 规则引擎核验 -> JEV 提供解释或排序建议 -> 人工/策略层复核 -> 受控执行器
```

已确认的策略阈值、预算上限、账户绑定、主计划范围与平台确认流程不由建议模型自行改写。模型不可用、超时或输出不符合 Schema 时，系统回退到确定性规则，不自动重试广告动作。

## 脱离 Codex 的实施路线

当前先稳定 Codex 浏览器投控、最新 Skill 与脚本复用。脱离 Codex 的运行方式作为后续兼容路线，使用本节验收清单时不改变现有执行会话。

1. **业务与宿主分离**：复用账户策略、数据契约、本地计算和记录；浏览器适配按目标宿主实现。
2. **浏览器读取**：验证本场罗盘与完整任务池，完成登录绑定、刷新、身份核验和数据质量检查。
3. **按钮库固化**：按实际需求逐个验证分页、编辑、暂停、删除和新建入口，每个成功动作立即保存回读证据。
4. **浏览器执行**：核验执行归属、未决请求与回执；结果未知时只查原对象，不换通道重发。
5. **保留接口验收**：分别验证已有 API 能力及本地 Playwright/CDP，不把文件同步或工具接通当作完整轮次验收。
6. **其他宿主交接**：在真实适配、调度和首轮验证完成后移交执行，旧会话不与接收会话同时操作同一主计划。

对外分别报告各通道的验收状态，配置或接口存在不等于完整业务流程已通过验收。

### 阶段 A：文档和契约稳定

- 固定账号、直播间、场次与独立策略的接口绑定，再定义可选的浏览器 Profile 和适配器接口；
- 把浏览器读取结果、API 结果和本地账本统一到同一份数据契约；
- 给每个适配器补充身份核验、刷新、读取、失败和回执测试；
- 明确各通道已支持、待核验及缺失的动作，执行判断沿用[运行边界](agent-contracts/portable-runtime-policy.md)。

### 阶段 B：独立浏览器运行时

- 由本机启动脚本打开指定 Profile；
- Playwright/CDP 连接本机浏览器；
- 复用已经登录的 Profile，不在聊天中传递 Cookie；
- 使用与 Codex 相同的读取工作流和结果文件；
- 浏览器失败时记录具体缺口；替代通道按用户当前选择与授权接入，未决提交先查原对象，不能自动重发。

### 阶段 C：客户交付包

- 程序、依赖和脱敏模板独立打包；
- 客户数据、Cookie、Profile、策略和历史回执留在本机；
- 安装器只初始化目录和配置，不覆盖已有运行数据；
- 通过版本清单、摘要和回滚保护程序更新；
- 在空账户目录、已有登录目录和多账号目录分别验收。

### 阶段 D：商业化与可选模型

## 验收标准

每个阶段至少提供以下证据：

1. 默认 Codex 浏览器流程能按本场交接完成读取、判断、动作回读及保存；浏览器只能连接指定账户的登录态；
2. 账号、广告户、主计划、直播间、开播时间或日期不匹配时，不向错误对象继续读取或写入；同广告户不同房间的 ROI 和策略互不继承；
3. 每轮浏览器读取都会刷新并保存原始页面证据、采集时间和页面更新时间；接口读取保留自己的来源时间；
4. 浏览器和 API 使用同一字段契约，无法确认的值保留为 `unknown` 或 `missing`；
5. 写入失败、结果未知、重复唤醒和页面刷新都不会盲目重试；
6. 选择其他运行方式时，分别验证 API 或该宿主浏览器适配与回执，不能沿用 Codex 的验收结论；
7. 产品到期或模型不可用不会自动停止既有广告，也不会放宽广告权限；
8. 发布包不包含 Cookie、账户 Profile、客户策略、任务回执和私有运行目录。
