## 入口与分工

日常投控按[项目通道约定](项目架构与演进路线.md#通道选择与兜底)使用 Codex CUA，优先复用本场交接的完整入口及[按钮库](浏览器按钮库.md)中已验证的脚本。下述本地 HTTP/CLI 接口属于独立的 Playwright/CDP 分支，其默认参数不代表 Codex CUA 的通道选择。

独立 Playwright/CDP 浏览器通道走本机 `POST /api/browser-boost`，由 Node.js 与锁定的 Playwright/CDP 适配器完成连续步骤。此入口仅走页面，失败不自动换 API。

同一核心供 Codex、dsh 和本机 CLI 调用。Codex CUA、dsh 宿主浏览器、Playwright/CDP 的登录态与证据分别登记，见[dsh 接入现状](#dsh宿主与通道边界)。本轮没有修改 dsh 的 Profile、域名权限或登录态。

| 动作 | 浏览器请求内容 |
| --- | --- |
| `list` | 刷新并读当前页，返回覆盖范围；不把当前页当全集 |
| `detail` | 核对任务 ID，打开数据/详情，保存完整本机证据后关闭 |
| `diagnose` | 打开可唯一定位的诊断面板，读取后关闭 |
| `create` | 素材追投或一键起量：指定形态、模式、总预算、总秒数及唯一名称；填写后独立回读 |
| `pause` / `resume` / `stop` / `delete` | 仅指定追投任务；回读明确状态，列表消失不证明删除 |
| `update_status` | 1 → resume，2 → pause，6 → stop；复用同一实现 |
| `update_budget` | `budget` 是修改后的总金额；必填实际旧值 `expected_budget` |
| `update_duration` | 新总时长 `duration_seconds` 与实际旧总时长 `expected_duration_seconds`；单位秒 |
| `update_roi` | 新目标及明确口径；真实表单元数据未知或冲突则不提交 |
| `update_bid` | 明确出价；沿用当前工具的数值范围和操作额度 |
| `update_audience` | 仅 `full_region`；各字段与选项核验齐全才填写和提交 |

动作名齐全不等于所有平台形态已验收。当前页面识别包含乘方与全域直播路径；商品卡没有本通道证据，返回待验证。平台明确不给当前对象提供动作时，保留平台拒绝或不适用的原因；不得把找不到控件直接写成“平台不支持”。

直播画面 `live_feed=true` 的入口尚未观察，浏览器请求明确返回 `browser_live_feed_pending_verification`，在连接或点击前停止；不会误走素材追投。画面、素材和一键起量不能混用，形态参数须为布尔值。API 通道的既有画面创建能力不受此限制。

## 绑定与预演

每次请求显式传 `account_id`、`primary_ad_id`；单任务动作还要 `target_id`。广告户来自本机注册账户，不能通过请求改成另一个广告户。日期 `start`、`end` 必须与实际页面控件一致，省略时按北京时间当天；不会静默切换到历史日期。

直播写入的房间、开播时间和范围来自该主计划的现有 `boost_write_scope`。提供执行归属时，`execution_owner` 与 `session_key` 必须配对，且与本机 owner 登记一致。页面未能证明场次、模式、容量或底线指标时，检查失败，不借 API 或旧快照补造浏览器证据。

`preview=true` 核对控件和表单、填写拟执行值、取消。预演返回 `before`、`requested`、`execution_allowed` 和失败原因，不点击提交。可能直接生效的状态按钮只定位，不为预演而点击。预演不等于操作授权或正式结果；`actual` 只来自提交后的独立读取。

预算 100 改为 200 的本地 HTTP 请求参数示意如下；占位身份须替换为本次真实绑定，示例不授予增额权限：

~~~json
{
  "account_id": "ACCOUNT_ID",
  "primary_ad_id": "PLAN_ID",
  "target_id": "TASK_ID",
  "action": "update_budget",
  "preview": true,
  "expected_budget": 100,
  "budget": 200
}
~~~

正式写入使用 `preview=false`，并填本次唯一 `request_id`。增加半小时不是传 1800 作为新总时长：原为 6 小时应传旧 21600、新 23400。已有任务时长修改仍要求有限期放量、新值 1800～86400 秒、半小时步进；预算和时长分开提交。超过普通预算比例的增额须满足已有具体范围授权。

## CLI 与插件

Agent 负责检查依赖与本机 CDP 登记，复用已安装环境。登录和验证码由用户本人完成。登记方法只维护在[本地 CDP 通道](#本地cdp通道)，不能复用 extension 绑定或静默搬移 dsh 登录态。

将业务 JSON 存在客户本机运行目录，再调用：

~~~powershell
node tools/browser-boost.cjs --request private-runtime/browser-request.json
node tools/browser-boost.cjs --request private-runtime/browser-request.json --execute
~~~

CLI 的写动作默认预演；`--execute` 才正式提交并沿用原 `request_id`。只连接本机已核验项目服务，端口可用 `--port` 或 `QC_PORT` 指定；不接受 Cookie、浏览器端点、选择器或 JavaScript。

Codex 插件命令为 `node bin/bridge.cjs browser-boost --request <本机JSON绝对路径> [--execute]`，继承插件的配置、数据目录和已核验服务。新源码需重新构建插件并重新加载插件，不能认为已安装的旧包自动获得新接口。dsh 可调用相同 CLI；宿主正式接入尚待单独验证。

## 执行检查与重复请求

浏览器通道复用现有身份、操作范围、场次、执行归属、预算前值、ROI 口径、恢复保护和调参额度检查。暂停不套删除的淘汰放行闸。检查失败返回可区分的原因及能证明的零广告写入结果。

正式浏览器写入先在 SQLite 的 `browser_boost_requests` 占用账户＋请求编号并绑定载荷摘要；提交前保存 submitted。相同编号和内容回查原回执，不再连接或点击。相同编号改参数冲突；API 创建编号不能改走浏览器，浏览器编号不能改走 API。预演不占正式写入编号。

同主计划操作在本机服务中串行；浏览器队列按规范化CDP端点分开，不再按整个登记文件排队，同端点沿用已有文件锁。排队期限到后返回零写入，后来获得锁也不执行。已存在的端点锁不抢占。其他进程、上游人工操作，以及旧通用控件脚本的独立证据目录不受这一完整互斥保证；不要同时操纵同一浏览器页面。原生会话入口仅使用进程内在途队列，不使用此旧服务的逐动作留档或文件锁。

提交后断线、状态未回读或回执无法持久化时，结果为 `unconfirmed`，`retry_write=false`。其他编号与 API 同主计划写入会被阻断。沿原编号回查回执，并用 list/detail/操作账本只读核验原对象；当前没有自动解除未决状态的接口，不删除数据库记录来解锁。

停止、删除等真实不可逆动作仍按[Agent 执行边界](agent-contracts/portable-runtime-policy.md)和用户本次授权处理，脚本支持不替代当次确认。

## 等待与速度

点击使用 Playwright 控件可见、可用和可交互的条件；数据读取还要求加载指示结束、表头与目标字段就绪。提交监听在点击前注册，提交后等待明确拒绝或指定对象状态改变，然后刷新同对象回读。采用[Playwright 自动等待](https://playwright.dev/docs/actionability)；持续轮询页面不以 `networkidle` 判断业务完成，见[官方加载状态说明](https://playwright.dev/docs/api/class-page#page-wait-for-load-state)。

业务流程没有固定睡眠。默认总期限 50 秒，连接和页面加载最多 15 秒，控件最多 5 秒，结果监听和回读最多 15 秒，每次取剩余期限的较小值。HTTP/CLI 传输留到 55 秒用于返回本机回执；传输超时不证明零写入，不触发重发。

连接池按端点、账户、主计划及日期隔离，使用前再次核对，闲置 5 分钟释放本进程连接；服务优雅退出也释放连接。正式独立读取仍刷新页面，不因连接复用跳过刷新。

回执记录 `connect_ms`、`load_ms`、`locate_ms`、`submit_ms`、`readback_ms`、`total_ms` 与 `connection_reused`。未进入的阶段不补零。定位阶段含准备中的加载，回读阶段含刷新，加载计时是子阶段，不能将这些数字直接相加。速度以验收表实测为准，不承诺固定秒数。

## 回执和本机证据

Codex CUA 已有完整罗盘和调控池回执时，可复用 `tools/codex-qc-round-record.mjs`：`summarizeRound(previous,current)` 按同场差分、精确字符串任务ID和真实采集间隔计算显示消耗速度；到期反馈继续保留，只有明确复评回执才结案，未知保留null。`saveRound({scene_dir,round_dir,previous,current,state_text,learning_text})` 保存完整轮次、最新回执与模型已写好的状态/学习文字，覆盖最新状态前核对原回执是否已被别轮更新；这是乐观冲突检查，不能称互斥锁。该模块只处理本机文件，无浏览器、广告、网络或调度调用，不替代逐动作检查点。预算摘要、反馈结案字段及新场加载最新版脚本见[摘要与接续契约](../skills/qianchuan-ops/references/新直播间接入与双宿主会话.md#紧凑数据包与一次判断)。

调控池读取同时识别“共N条记录”和“共N条任务”。无分页时，只有当前身份/日期/筛选及表头核验成功、明确零任务、可见“暂无数据”且无加载或失败提示，才返回`empty_verified:true`；缺数、冲突计数和仅有空表均不算零任务。两条通道分别用离线页面回归，不能称为本次真实千川浏览器动作验收。

工具返回操作 ID、请求编号、前值、请求值、实际回读、结果状态、分段耗时及证据位置。列表只给业务字段，详情与诊断正文最多 2000 字符；完整表格或面板原文保存在本机。缺失值保持未知，不能把填过的表单值当成回读值。

执行证据位于实际 `QC_RUNTIME_DATA_ROOT/browser-boost/runs/`，逐控件和动作完成后立即独占保存 JSON，再进入下一项；提交、结果及失败另行记录。证据包含通道、观察时间、目标绑定、定位依据和结果。隔离页面明确标 `evidence_origin=isolated_fixture`；测试成功不登记为实机 `write_verified`。

关键实现入口：`tools/browser-boost.cjs`、`tools/lib/playwright-boost-operations.cjs`、`server-app/server/lib/browserBoostService.js`。请求契约在 `browserBoostContract.js`，持久请求在 `browserBoostRequests.js`；HTTP 和 CLI 不另维护一套浏览器操作逻辑。

### CUA 与 CDP 的证据边界

历史 CUA 验收覆盖账户、主计划、日期和列表核对，按 ID 选择与取消，打开表单、填写预算和时长并取消；当时没有正式提交。数据图标遇到平台网络或服务异常，记录为尝试失败。后续 CUA 成功动作已有独立登记，不替代 Playwright 的绑定和逐动作验收。

同日的隔离回归覆盖参数、持久编号、重复请求、同目标并发、断线和回执失败。真实 CDP 连接到隔离 HTML 仍不是千川实盘；测得的毫秒数不作为生产时延承诺。

### 留待实盘的验收

1. Agent 接上正确账户的本机独立 CDP 窗口，必要时由本人登录，先验证身份、日期、正式刷新和列表范围。现有 CUA 登录已可用，不要求重复登录它。
2. 按乘方、全域直播、商品卡实际页面核验入口、表单和取消，每完成一个动作立即保存本通道定位与证据。缺少的商品卡页面适配只依据真实观察补齐。
3. 在当次允许的测试对象上逐项提交并回读。停止、删除不因历史授权自动执行；未开播的拒绝与已回读业务成功分别计数。
4. 确认场次、容量和 room_floor_roi 等检查所需的原生字段；当前字段不足会阻断相应写入，不能为试跑而放宽守卫。
5. 测量真实冷连接、重复读取与写后回读；再完成 dsh 正式接入和新的插件构建/加载验收。

## 浏览器读取与建议

日常调控通过浏览器插件读取原始页面，由模型判断。下述采集、隔离账本和本地 HTTP 快照接口用于专项验证或独立分析，不是日常调控前置步骤。默认通道见[通道选择与兜底](项目架构与演进路线.md#通道选择与兜底)。

### 本地 Playwright/CDP 通道

本地通道使用 tools/playwright-channel.cjs 的 read_boost_table 动作，调用方式见[本地 CDP 通道](#本地cdp通道)。它使用独立的 playwright-cdp 账户登记，返回相同的原始 capture 契约，后续仍可走本文的本地快照登记流程。

适配器 tools/lib/playwright-browser-adapter.cjs 同时提供读取和控件操作能力，执行判断由 Agent 根据用户任务作出。追投表读取动作只负责采集。runQianchuanReadWorkflow 继续属于 CUA 入口，拒绝 browser_adapter、playwright_bindings_file 及 CDP 身份，避免借用 CUA 脚本和成功证据。CUA、dsh、本地 CDP 的回执分别登记。

本地通道的真实账户登录、绑定和页面动作仍待验收；模拟测试不能替代实机证据。浏览器失败、空表或未知结果必须保留缺口，不能伪造新鲜数据，也不能据此重发结果未知的广告写入。

### 单轮入口

已选择 CUA 通道时，重复读取使用 [codex-qc-read-workflow.mjs](../tools/codex-qc-read-workflow.mjs) 的 `runQianchuanReadWorkflow(tab, binding, options)`：一次 CUA 调用完成刷新、核验、整页读取、清洗、隔离账本保存及回读，直接返回简表与分段耗时。已确认的页签和绑定可以复用，不必每轮重新探索按钮或人工组装报告。

首次由 Agent 在已连接的 Codex CUA 中准备同一标签的 AX 与 Playwright 句柄，再加载模块。下面的 `moduleUrl` 是项目内该文件的本地 `file:///…` 地址，`binding` 是本轮明确的账户、广告户、计划和日期；不能从前端选择自动猜测。

```js
const reader = await import(moduleUrl);
const boundTab = {
  playwright: driver.playwright,
  url: () => driver.url(),
  reload: () => driver.reload(),
  getAXState: options => axTab.getAXState(options)
};
nodeRepl.write(await reader.runQianchuanReadWorkflow(boundTab, binding, {
  tab_key: `${browser.browserId}:${driver.id}`,
  node_executable: installedNodePath,
  profile_bindings_file: "D:/…/private-runtime/browser-bindings.json",
  browser_identity: {
    browserId: browser.browserId,
    browserType: "extension",
    profileName: browser.profileName,
    metadata: { extensionInstanceId: browser.metadata.extensionInstanceId }
  }
}));
```

准备完成后，重复执行最后一次调用即可。Node 路径由 Agent 查找已有环境；省略时使用 PATH 中的 `node`。浏览器动作始终在 CUA 内完成，本地子进程只处理 JSON/SQLite，不接管浏览器。身份显示不完整、加载未完成或日期不符时返回失败，不复用旧快照。

### 录制带式浏览器追投回放

重复的画面追投创建使用 [codex-qc-boost-replay.cua.js](../tools/codex-qc-boost-replay.cua.js)：核对 URL 和账户 → 定位素材 ID → 点击该行“追投” → 保存原生名称、填写参数 → 提交 → 精确回读原任务。统一会话入口已核页面时传 `refresh:false`，复用可见素材入口，避免重复刷新导致控件失效。命名与提交账按[统一会话契约](../skills/qianchuan-ops/references/新直播间接入与双宿主会话.md#codex统一会话入口)，不使用内部请求编号覆盖原名。正常流程只取必要元素，真实入口失败才保存当前页面证据。

入口默认 `execute:false`，只填写并取消，用于检查定位和字段；只有本次明确授权时才传 `execute:true`。参数必须显式绑定 `advertiser_id`、`primary_ad_id`、`material_id`、`budget`、`duration_hours` 和 `count`。提交后必须回读任务 ID 才算 `write_verified`；页面切到“调控”、提交超时或任务 ID缺失时立即停止，不重复提交未知结果。

```js
const replay = await import(moduleUrl);
nodeRepl.write(await replay.replayQianchuanBoostCreate(tab, {
  advertiser_id: "60000009",
  primary_ad_id: "60000012",
  material_id: "60000011",
  budget: 100,
  duration_hours: 5,
  count: 5,
  execute: true
}));
```

回放使用固定定位和短等待，速度会接近人工录制动作；首次连接浏览器、页面刷新和平台自身提交延迟仍会计入总耗时。它只适用于已经核验过的乘方详情页和直播间画面素材行，不把历史素材 ID 当作新账户默认值。

生命周期动作使用同一文件的 `replayQianchuanBoostAction`：按 `target_id` 搜索并选择唯一任务后，可回放 `pause`、`resume`、`stop` 和 `delete`，写后必须回读状态。`delete` 仍要求页面确认弹窗，且只对本次授权的目标执行。当前乘方调控列表没有稳定的预算/时长编辑控件证据，传 `action:"update"` 会返回 `browser_update_not_verified` 并停止，不会猜测或误点；预算和时长修改要等单独完成页面验收后再接入。

2026-09-24 在沈荡户旧全域历史日期页最终实测：9 行、18 列，浏览器采集 2992ms、本地收尾 202ms、总计 3199ms。这个数字是已连接标签的单轮耗时，不包含首次连接浏览器及模型回复时间；它证明入口已串通，不承诺平台统计延迟或每轮固定时长。

这个快速入口使用**隔离本地账本**。传入 `profile_bindings_file` 和 `browser_identity` 时，返回 `registry_used:true`，并在回执中记录脱敏的 Profile 绑定证据；省略它们只适合兼容调试，不能作为多账号正式运行方式。隔离账本不等于本地服务登记。它不合并直播场次、不产生投放建议、不自动翻页、不改变筛选。`tab_key` 防止同一 CUA 模块实例重复读取同一标签，不是跨进程互斥锁。`timings` 记录准备、采集、本地保存回读和总耗时；总耗时不含首次连接浏览器及模型组织回复的时间，也不能保证每次页面加载一样快。

专项分析需要把快照登记到本地 HTTP 服务时，使用下列已有分步入口：

1. 先查[按钮库](浏览器按钮库.md)，在已经登录且明确绑定广告户、主计划和日期的追投列表上工作。不要把浏览器名字或登录用户当作广告户。
2. 在 Codex 浏览器会话中读取并定义 [codex-qc-read-once.cua.js](../tools/codex-qc-read-once.cua.js) 的 `runQianchuanCapturePage`。传入 `account_id`（本机键）、`advertiser_id`（平台户）、`primary_ad_id` 及 `date` 或两个元素的 `date_range`；调用方同时传入计划类型/商品上下文时，必须与当前页面和本机计划登记一致。这是 CUA 脚本，不能直接用 Node 运行；也不依赖字符串 `eval`。计划类型或商品上下文无法从当前页面核验时，先停止本轮读取。
3. `tab` 提供 `playwright`、`url()`、`reload()` 和 `getAXState()`。前两类来自同一个已连接浏览器标签；若宿主把 AX 与 Playwright 分开提供，用同一标签的两个句柄适配，不能混用标签。
4. 脚本每次先核对身份，刷新，等待明确的页面身份和表格，再读取原始表头、单元格，并复核身份和表格未变化。`ok:false` 时不登记成功，也不把旧结果当新数据。
5. 将原始 `capture` 提交给本地 `/api/browser-snapshot` 接口，按同一账户与返回的 `snapshot_id` 回读。不能将手写指标作为原始采集包。

服务端 HTTP 对应 /api/browser-snapshot 的 POST/GET。账户必须已登记且平台户映射一致。快照和轮次属于本地记录，远程请求仍检查访问令牌；该入口不产生广告写入。

### 原始数据与清洗

采集包 `schema_version` 为 `1.0`，包含 `binding`、`page`、`timing`。`page` 保存 URL、日期、计划类型、原始表头和每行单元格；原文保留，汇总行与任务行分开。按列名匹配指标，不用第几列猜含义。

时长统一派生为秒，同时保留原始单元格；只转换已验证的明确单位格式。未知格式不参与时长建议。创建时间按页面北京时间解析并带 `+08:00`。刷新开始、刷新完成、采集时间和页眉更新时间分别保存。回读时重新计算采集是否超过 90 秒，不修改历史证据；新刷新不保证平台统计本身无延迟。

### 多选和页容量

[codex-qc-list-controls.cua.js](../tools/codex-qc-list-controls.cua.js) 只封装乘方列表的当前页精确多选、取消与 20/50 条切换，不点击删除、暂停等提交按钮。未知跨页选择会拒绝，100 条尚不支持。先核对身份和现有选择，返回实际勾选 ID 集合；每个控件成功后及时保存按钮证据。

此前手动验收覆盖乘方控件；新脚本已完成隔离测试，仍需真实乘方页面复验。当前沈荡户页面显示“账户主体与店铺主体不一致，当前已停止投放”，因此本轮不能进入追投列表，未把失败误记为脚本成功。跨页选择由用户说明可用，但全量跨页脚本未验收。列表读取永远标为 `current_page_only`，不能据此认定全场任务数或补建缺口。

### 离线导入和验证边界

`node tools/import-browser-snapshot.cjs --input <capture.json> --output <receipt.json>` 只预览清洗结果。加 `--ledger-dir <项目work内隔离目录>` 可保存并核对回读；不会查询真实账户注册表，所以回执明确 `registry_used:false`，不等于本地服务登记。输入与输出不能相互覆盖。

## 本地CDP通道

入口 tools/playwright-channel.cjs 通过本机 Chrome 的 CDP 端点读取追投列表、页面原文或操作单个控件，使用 server-app 中锁定的 playwright-core。Agent 检查和安装依赖、准备独立浏览器 Profile；只有登录等本人步骤交给用户。

当前已通过模拟浏览器的隔离、并发、去重及断线回归，并在独立无头 Chrome 测试页通过真实 CDP 连接、DOM 读取和服务端采集契约校验；尚未连接真实千川账户验收。通用控件入口不等于已经封装完整追投流程；CUA 和 dsh 的成功证据不能计入本通道实测。

完整追投业务应使用[浏览器追投工具](浏览器追投工具.md)中的 `manage_boost(execution_channel="browser")` 或固定 CLI，复用业务守卫与操作账本；逐动作实测状态见[验收表](浏览器追投工具.md#能力验收与待办)。下文仍是单控件/读取适配器入口，不绕过业务工具直接提交广告。

### 独立账户登记

另建 private-runtime/playwright-bindings.json，不复用 extension 登记或 dsh 的 storage-state。空模板为 release/templates/playwright-bindings.example.json。每个账户使用独立 Profile 和本机端口，同一端点不能分配给多个账户。

~~~json
{
  "schema_version": 1,
  "bindings": [{
    "account_id": "ACCOUNT_ID",
    "browser_type": "playwright-cdp",
    "profile_name": "PROFILE_NAME",
    "cdp_endpoint": "http://127.0.0.1:9222",
    "status": "active",
    "advertisers": [{
      "advertiser_id": "ADVERTISER_ID",
      "primary_ad_ids": ["PLAN_ID"]
    }]
  }]
}
~~~

所有身份值替换为本机真实绑定。Profile 名称来自登记，不是 Chrome 返回的身份认证。连接后按可信千川 URL 的广告户和主计划参数选择唯一页面，每次操作重新核验；多个匹配、登录跳转、切户或断线均报错。业务页面的 DOM 身份、场次及日期仍须按实际页面核对。

### 调用

~~~powershell
node tools/playwright-channel.cjs --bindings private-runtime/playwright-bindings.json --request private-runtime/cdp-request.json --check
node tools/playwright-channel.cjs --bindings private-runtime/playwright-bindings.json --request private-runtime/cdp-request.json
~~~

--check 只检查依赖和登记绑定，返回 browser_verified:false，不打开浏览器或证明登录有效。实际调用要求 Chrome 已开启本机 CDP，目标页已登录且可以唯一匹配。启动参数、独立数据目录和端口由 Agent 按本机安装核验后设置，不修改 dsh 配置或链接目录。

读取请求示例：

~~~json
{
  "request_id": "read-20260926-0001",
  "account_id": "ACCOUNT_ID",
  "advertiser_id": "ADVERTISER_ID",
  "primary_ad_id": "PLAN_ID",
  "action": "snapshot"
}
~~~

支持 snapshot、read、read_boost_table、click、fill、press、check、uncheck、selectOption。read 和控件动作提供 locator，可用 role 加 name、text 或 css，要求唯一匹配。fill、press、selectOption 同时提供字符串 value。定位参数须来自当前页面证据，不预填未经本通道验证的千川选择器。

控件动作可附 readback，包含 locator 和 expected_text。文字不符返回 readback_mismatch，保留待核验状态。文字匹配只证明该文字出现，仍须绑定真实业务对象及变化后才能登记 write_verified。日期需要校验时提供 date 或 date_range；不把未传日期的快照称为指定日期的完整结果。

### 读取追投列表

把请求中的 action 改为 read_boost_table，同时提供 date 或 date_range。独立读取模块是 tools/lib/playwright-boost-read.cjs，不导入或执行 CUA 脚本。该动作读取当前页，不点击投放按钮、不切换筛选、不自动翻页。

~~~json
{
  "request_id": "boost-read-20260926-0001",
  "account_id": "ACCOUNT_ID",
  "advertiser_id": "ADVERTISER_ID",
  "primary_ad_id": "PLAN_ID",
  "date": "2026-09-26",
  "plan_type": "cheng_fang",
  "action": "read_boost_table"
}
~~~

上例日期和所有身份均须替换为本次任务的实际值。plan_type 可省略；提供时只能是 cheng_fang 或 quan_yu，并且必须匹配页面。仍用前面的两条命令检查和调用。

脚本核对 URL、页面账户 ID、计划 ID 及日期控件，刷新后等待表格就绪，再读取两次表格和筛选状态。加载未完成、空表或读取期间数据变化会有限重读，每次重新采集都先刷新，最多三轮；身份变化、重复任务 ID、表格歧义和结构不符立即失败。页眉时间保留原文，采集时间独立记录。19 位任务 ID 和横杠等未知值保留原文。

采集结束前复用服务端 normalizeBrowserBoostCapture 校验必需列、单位及任务 ID；缺少“调控消耗”等关键列时不报告采集成功。成功返回 capture（schema_version=1.0）、attempts、coverage=current_page_only 和 action_evidence。capture 可按[浏览器读取与建议](#浏览器读取与建议)交给本地 `/api/browser-snapshot` 的 POST，再以 GET 按原 `snapshot_id` 回读；脚本本身不自动写生产账本。当前采集不绑定直播场次，不凭页面列表做本场投放结论。

表格必须能明确归属到唯一表头；表头、表体分离等未经验证的结构会报缺口。全域页保存实际筛选及关键词；乘方筛选控件仍未取得独立定位证据，保留 null。因此当前页任务数不能代表全账户任务数，空表也不能作为零任务或补建依据。

定位依据来自已有页面观察，本地 CDP 的成功证据须重新取得。模拟测试只证明代码行为，不计入实机按钮验收；当前真实账户的 CDP 登录、绑定和页面验收仍待完成。

### 回执、重试与并发

回执默认写入 private-runtime/playwright-channel/，带 channel=playwright-cdp、账户、请求编号、动作、时间和结果。正式读取先刷新；刷新时间和采集时间分别记录，页眉时刻不能替代它们。空值、横杠、未知或加载中报 page_data_unavailable，不转成零。snapshot 是页面原文，字段有效性、表格完整性及平台延迟需要另行核验。

read_boost_table 每完成身份核对、刷新、表格读取中的一个动作，即保存对应 -action-N.json 和本请求的 -actions.json 登记，然后继续。这些文件与主回执同目录，均标注 channel=playwright-cdp；不覆写 CUA 或 dsh 的登记。注入适配器的测试回执标 evidence_origin=injected_adapter，真实连接标 live_cdp。

每个调用完成后先保存本动作回执，再开始下一个。按钮登记统一遵守[浏览器按钮库](浏览器按钮库.md)。通用读取成功标 read_verified，仅证明本次绑定页面读取完成；控件调用标 opened、业务效果 unconfirmed、advertising_writes=null。提交后异常也不报告零写入。

相同账户及 request_id 再调用只返回原记录，replayed:true，它不是新采集。相同编号更改参数或绑定会冲突。需要新读取时使用新编号；结果未知的写入不能换编号重试。API 与浏览器间也遵守这个规则。

同一证据目录内，端点锁以文件独占创建实现跨进程串行；不同端点可独立运行。它不覆盖其他证据目录、CUA 或 dsh，不能称为跨宿主互斥。锁遗留时先核验原进程和未决请求，不自动抢锁。

### 服务巡检与依赖

Agent 可运行 node tools/setup.cjs --check --json 检查环境，再用 node server-app/scripts/start-workbench.js --health --json 检查本项目服务。检查失败按输出处理，不擅停同端口的陌生服务；一次检查不自动创建周期任务。

依赖从 server-app 锁文件安装，可用时复用。server-app/server/lib/browser.js 只保留 HTTP 总览读取，旧浏览器启动与探针已移除，/api/probe 返回 410 browser_probe_retired。CUA 文件继续只在对应宿主中执行。

执行判断见[Agent 决策与工具执行边界](agent-contracts/portable-runtime-policy.md)，配置保护见[dsh 接入现状](#dsh宿主与通道边界)。凭据、Profile、登记及运行回执仅存本机，不进入通用包。

### Playwright控场模块

独立模块：`tools/qc-control-pools.playwright.cjs`。从当前 CUA 逻辑移植，接收标准 Playwright `Page`，不导入 CUA 文件、不需要 Codex 浏览器插件或工作台服务。保留原 CUA 脚本和当前定时任务。

项目现有 `server-app/node_modules/playwright-core` 1.63.0 可直接复用。浏览器启动、登录和连接由调用方提供；使用本机 CDP 时沿用[本地 CDP 通道](#本地cdp通道)的独立账户登记，不能把插件连接或登录态登记冒充 CDP 绑定。

#### 顺序闭环

使用同一个已核对账户、主计划和日期的追投页面。每轮先读取暂停池，判断回补和恢复；需要恢复时用单条恢复函数并立即留证、回读。然后读取调控池，判断暂停或调整时长。人工选择和未提交表单会阻断筛选变更。

```javascript
const ops = require('../tools/qc-control-pools.playwright.cjs');
// controlPage、livePage 为调用方已连接的原生 Playwright Page。
const cfg = {
  account_id, advertiser_id, primary_ad_id, room_id, live_start_time, date,
  min_net_roi, online_cap, response_wait_ms, // 从本场有效策略读取
  on_checkpoint: saveCheckpoint // 必须即时保存；通道 playwright-cdp
};
const paused = await ops.readQianchuanControlPool(controlPage,
  {...cfg, pool: '手动暂停'});
// paused.ok 后由 Agent 判断；恢复动作另传精确ID、理由、execute:true。
// 恢复未知先核原对象，不重发；恢复成功回读后才继续。
const active = await ops.readQianchuanControlPool(controlPage,
  {...cfg, pool: '调控中'});
// active.ok 后由 Agent 判断暂停/时长动作；不要把策略写成自动全恢复。
```

只读整轮可调用 `runQianchuanBrowserRound({control_tab: controlPage, live_tab: livePage}, {...cfg, execute:false, previous_round})`，同页先暂停后在投，返回两池及罗盘差分，`actions`为空。它只采集，不能代替需要在两阶段之间执行恢复的外层闭环。

导出单条/精确对象操作：`replayQianchuanControlPause`、`replayQianchuanControlResume`、`replayQianchuanControlDuration`，及零单辅助 `pauseQianchuanZeroOrderTrials`。默认干跑，写入须有用户当前授权并明确传 `execute:true`。参数与 CUA 版一致；时长动作需要预算与时长前值、目标时长和理由。副本不新增预算、不隐式创建任务。

`on_checkpoint` 保存 DOM、来源时间和绑定，每个动作完成后才继续；真实写入按[工具取证约定](../skills/qianchuan-ops/SKILL.md#必要边界)保存精确对象前后回读，不要求截图。副本回执与 CUA 分目录保存，不能复用 CUA 的实机成功状态。模块本身不提供调度、CDP 端点锁或创建请求去重，生产调用方沿用现有通道的绑定、串行和操作账本；不要与现有 CUA 循环同时写同主计划。

### 二、动项目时不要碰的线

1. **不要改或删 profile 补丁里的 `- id: browser` 段**，尤其 `allowedHosts` 与 `storageStatePath`。要改先确认。
2. **不要把 `private-runtime\dsh-browser\` 纳入发布包或版本库**，也不要打印其中内容（含实时登录凭据）。
3. **不要移动或删除 `../弈/dsh-presets/`**：profile 是 `link:` 依赖，目录一移，模式的加载就废。
4. `tools/codex-qc-*.cua.js` 是 **Codex CUA 专用**（文件头写明"不是独立 Node/Playwright CLI"）。若要新增本地通道，走既有骨架 `tools/lib/playwright-browser-adapter.cjs`，并**另建 `playwright-cdp` 类型的绑定登记**——现有 `private-runtime\browser-bindings.json` 是 `extension` 类型，两套绑定校验不通用。
5. server-app/server/lib/browser.js 的遗留浏览器启动与采集探针已移除，只保留显式账户的 HTTP 总览读取；/api/probe 返回 410 browser_probe_retired。本地浏览器操作使用[独立 CDP 通道](#本地cdp通道)，不重新启用旧路径。
6. 新增或修改浏览器脚本时，按[浏览器按钮库](浏览器按钮库.md)的纪律登记：每验证成功一个动作立即登记 + 留回读证据；**跨通道（CUA / dsh 宿主 / 本地 Playwright）的动作与证据分开登记，不能互相冒充**。
