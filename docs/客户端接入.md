# 运行环境与客户端接入

按需进入：[环境与依赖](#运行环境与依赖) · [Skill 同步](#技能正文与安装副本) · [工作区建立](#工作区建立与接续) · [账户接入接口](#账户接入与配置契约)。客户本人需要做的步骤见[用户引导](用户引导.md)。

Agent 负责运行环境、项目依赖、服务启动和 Skill 与浏览器接入。已有接入先核验并复用；以下命令在千川工作台程序目录运行，客户项目路径按宿主实际选择填写。

数据查询能力见[API功能图](逆向API功能图.md)。直播读盘与调控使用宿主浏览器插件。

## 运行环境与依赖

用户只需说“帮我运行”。有本机操作能力的 Agent 负责下面的检查、安装和验证，不让用户执行命令、下载依赖或填写路径。只有系统授权、账户登录、验证码等必须本人处理的步骤才请用户介入。

### Windows

1. 执行 `node --version` 和 `npm --version`。优先复用本机或 Agent 已有的运行环境；Node 至少为 22.5。能运行时不要重新下载或无故升级。
2. Node/npm 缺失或不满足最低版本时，检查系统是否有 WinGet。可以使用时，Agent 执行下面的安装命令；这是 Microsoft 软件源中指向 nodejs.org 的 Node.js LTS 安装包：

```powershell
winget install --id OpenJS.NodeJS.LTS --exact --source winget --silent --accept-package-agreements --accept-source-agreements --disable-interactivity
```

3. 检查退出结果。在新的命令会话中重新验证 `node --version`、`npm --version`；现有会话未更新 PATH 时，由 Agent 刷新自身进程环境或使用已核验的绝对路径，不让用户手工配置。
4. WinGet 缺失或安装失败时，先读错误，不反复执行相同失败命令。Agent 从 [Node.js 官网](https://nodejs.org/en/download) 获取适合本机架构的安装包或便携包，核验官方摘要或签名后安装。下载文件放项目 work；不关闭杀毒软件，不忽略摘要不匹配，不绕过系统授权。可用用户级便携安装时优先采用，路径由 Agent 管理。
5. 若系统要求本人确认安装授权，明确告知用户只需处理该授权；完成后 Agent 自行续接。不要把整个安装过程交回用户。

WinGet 参数以 [Microsoft 安装说明](https://learn.microsoft.com/en-us/windows/package-manager/winget/install) 为准。不要添加忽略安全哈希检查的参数，也不要更换为来源不明的下载站。

### 安装项目依赖并启动

Node/npm 可用后，在项目根目录执行：

```powershell
node tools/setup.cjs --check --json
node tools/setup.cjs --json
```

第一条只检查。首次缺少项目依赖或尚未初始化是正常结果，继续第二条；第二条会按需安装依赖、初始化并启动。已有配置冲突时按错误处理，不覆盖账户和 Cookie。以启动结果的 ok、service_online、url 和 next_step 为准，不把安装命令退出成功当成全部接入完成。

网络或权限失败由 Agent 诊断后限次重试。下载途中不要另起并行安装；不要因为缺少可选开发工具而让用户安装整套开发环境。正常启动以后接着完成账户引导。

### 其他系统与客户端

macOS/Linux 上由 Agent 使用已有可信包管理器或 Node.js 官方包安装同等运行环境，再执行项目初始化。当前验收环境是 Windows，其他系统尚未完整实测。

纯聊天软件没有本机操作工具时，无法自己执行安装；请用户改用有本机执行能力的 Agent，或启动项目里的“开始使用.cmd”。不能声称没有工具的软件已经完成安装。

## Codex

```powershell
node tools/connect-client.cjs --project-root "客户项目绝对路径" --client codex --json
```

脚本只在客户项目 `.agents/skills/qianchuan-ops` 建立 Skill 链接。已有同名链接指向其他位置时停止，不覆盖。读取返回的 Skill 路径，按宿主方式加载并核验引用。

## Hanako 与其他客户端

执行 `node tools/connect-client.cjs --project-root "客户项目绝对路径" --client manual --json` 获取随包 Skill 入口。按宿主方式加载；自动发现未核实时标记“按路径可用”。

## 技能正文与安装副本

通用技能唯一正文为程序包 `skills/qianchuan-ops`。新安装优先目录链接；经用户要求，也可先合并已有副本独有修改，再将项目、Codex全局、DSH及Hanako的同名入口改成指向此目录的链接。修改任一链接入口就是修改同一份正文，不需要多处复制。同名全局Skill的发现顺序与宿主实际加载仍须核验，链接/哈希一致不证明正在运行的会话已重读。

Windows已有副本迁移用`tools/link-qianchuan-skill.ps1`，只处理显式目标的同名Skill，不改其他Skill、Profile、MCP配置或凭据。先检查差异并合并独有内容，再用本次digest执行：

```powershell
./tools/link-qianchuan-skill.ps1 -TargetPath "安装入口绝对路径"
./tools/link-qianchuan-skill.ps1 -TargetPath "安装入口绝对路径" -Apply -ExpectedDigest "检查返回的digest"
```

脚本核绝对目标和备份边界，将原目录完整迁入`work/skill-sync`，优先建SymbolicLink，系统缺少该权限时用Junction；两者均共享目录内容。新增个人文件或并发修改会停止，建立失败则在未产生目标条目时恢复原目录，不删除原文件。校验链接目标与完整文件清单后留回执。程序目录搬迁后修复链接；正在运行的会话在下一次动作前读取变更正文，不宣称自动刷新模型上下文。

确实无法使用链接的环境才保留独立副本，通过现有同步工具更新：

```powershell
node tools/sync-qianchuan-skill.cjs --check --target "安装副本绝对路径"
node tools/sync-qianchuan-skill.cjs --apply --target "安装副本绝对路径" --expect "上一步返回的digest"
```

Agent 先审阅 `changes` 和 `extras`。工具在 `work/skill-sync` 保存被覆盖原文，按预期哈希校验源文件与目标，再写入并回读；发现新增个人文件或并发修改会停止，不删除副本或额外文件。用户资料继续留在客户自己的工作区，不能为发布而复制进通用技能。发布包沿用白名单；本机历史经验不自动加入分发。

## 验收

1. 读取 Skill，检查任务所需引用文件。
2. 如使用本机数据工作台，核对进程入口、回环地址和配置根目录。
3. 使用宿主浏览器插件核对当前账户、主计划和场次。
4. 分别记录文件安装、Skill加载、浏览器核验和实际操作结果；未在播时不称实盘通过。

## 工作区建立与接续

### 多会话的文件归属

初始化只建立公共入口、状态和基础目录。核验账号后直接建立该账号的独立任务，核验场次后准备循环、执行归属和接续状态；根接续状态只存公共部署信息。完整约定见[多账号多会话](定时与循环任务.md#多账号与会话隔离)；本节用于解释下文单任务示例中的“当前任务”和“接续状态”。

Agent 先确认宿主当前选中的项目。程序文件留在千川工作台项目内；客户的策略、任务和复盘写在客户选中的项目里。初次接收完整项目时，这两个目录通常相同。

### 第一次建立

先读取客户项目现有 AGENTS.md 和索引。客户已经有自己的工作区布局时沿用：在接续状态里记录程序目录、工作区目录、策略、任务和复盘位置，不强制新建 workspace/。

没有既有布局时，在千川工作台程序根目录执行下面的命令。Agent 将引号里的示意文字替换为宿主提供的真实绝对路径，客户不用手填：

```powershell
node tools/init-workspace.cjs --project-root "当前选中的项目绝对路径" --json
```

命令在所选项目的 workspace/ 建立：
- .qianchuan-workspace.json：程序、客户项目、客户工作区和内置入口的本机路径。
- 工作区索引.md：去哪找流程和记录。
- 接续状态.md：公共部署进度；业务接续状态在具体任务目录。
- AGENTS.md：新工作区的读取入口。
- 部署检查.md：环境、Skill、浏览器、Cookie 路径与调度能力的核验结果。

主项目根目录没有 AGENTS.md 时补建读取入口；已有则保留。后续新 Agent 从根目录即可找到接续状态。

已有同名文件保留，不覆盖；路径冲突、链接或无效映射会明确报错。修复前先核对真实目录，不删除旧文件来“消除报错”。该命令不安装依赖、不登录、不创建账户、不启动调度、不进行投放。目录搬迁后必须核对映射，不能默默继续使用旧绝对路径。

客户项目和千川工作台目录不同时，程序与服务仍在千川工作台目录运行；生成的本机入口链接指向它，客户文件留在所选项目。不要只复制客户 workspace/ 就宣称完成软件交付；给其他电脑使用应交付完整的通用项目。

同时建立五个基础目录：账户策略/、任务/、任务卡/、素材分析/、复盘报告/。已有目录和内容保留；遇到链接或同名文件冲突停止并报告，不覆盖。账户、日期及场次子目录等取得真实身份后再建立。

### 接入后建立业务文件

Agent 根据真实数据填写，不要求客户创建文件或抄 ID：

具体布局只在[多账号多会话](定时与循环任务.md#多账号与会话隔离)维护。按其中的账号、场次目录建立策略、任务、循环、接续及执行归属文件；未开播放账号的准备目录，不预造场次。

既有账户名目录可以沿用，在索引记录真实 account_id 和绝对路径即可。任务模板只保留在程序目录，客户任务目录不另放共享副本。根接续状态只存公共环境，各轮业务进度写本任务的接续状态。

客户选择“当前策略.md 作为唯一盯盘入口”时沿用这个布局，不再生成任务或循环文件副本。每轮重读本账号当前策略，执行状态保存在同账号目录的运行状态.md，包含真实场次、任务 ID、授权、执行归属、调度和台账回执，不能复制规则参数。将本机映射的 customer_layout.type 记录为 account_strategy_entry；初始化会尊重该布局，不重建任务目录。账号与场次绑定要求见[多账号多会话](定时与循环任务.md#多账号与会话隔离)。

模板使用程序里的 [账户资料](../skills/qianchuan-ops/assets/workspace/账户资料.template.md)、[当前策略](../workspace/账户策略/当前策略模板.md)、[盯盘任务](../workspace/运行入口/盯盘任务模板.md)、[复盘模板](../workspace/运行入口/复盘模板.md)。复制到客户目录后填写，保留项目内的空白模板。

只预建上述五个基础目录，不预造账户、场次和历史记录。每次任务结束更新接续状态：记录已核验事实、时间、下一步和已经问过但未回答的问题；下次 Agent 先读它，再核验实时状态。旧聊天记录不替代最新接口数据。

### 首次读取与准备顺序

1. 先读当前主项目的 AGENTS.md，再读程序根目录的 AGENTS.md、AGENT_START.md；确认主项目与程序的真实路径，不能把附属程序目录当成客户记录目录。
2. 读本文件、[用户引导与缺项问答](用户引导.md)。已有工作区先读其映射、索引、接续状态，沿用已完成工作。
3. 执行初始化命令，回读五个工作区文件、主项目入口和五个基础目录；已有自定义布局按映射检查等价位置，不强制迁移。检查运行环境、依赖、服务身份和浏览器连接，具体执行 AGENT_START 第 2 步及[依赖安装](客户端接入.md#运行环境与依赖)。
4. 读[项目知识入口](../AGENT_KNOWLEDGE.md)和[随包技能](../skills/qianchuan-ops/SKILL.md)，核验已有账户、千川和罗盘接入、主计划及实际权限；缺项一次问一个。账户确定后建立账户资料与当前策略文件，未知项明确待补。凭据只保留在本机运行目录，不抄入交接文档。
5. 准备盯盘时依次读[日常接续](../workspace/运行入口/日常接续.md)、[数据读取纪律](../workspace/运行入口/数据读取纪律.md)、[投手决策](../workspace/运行入口/投手决策.md)、[盯盘提示词](../workspace/运行入口/盯盘提示词.md)、[任务模板](../workspace/运行入口/盯盘任务模板.md)、[循环指令](../workspace/运行入口/loop指令.md)。将真实任务保存到客户目录，明确频率、停止条件、权限、数据口径、逐轮决策留底和通知偏好。只做首次接入时可以准备待启用的任务文件，但不伪造已绑定场次或已启动定时安排。
6. 盯盘启动前阅读[复盘指令](../workspace/运行入口/复盘指令.md)及[复盘模板](../workspace/运行入口/复盘模板.md)，预先明确下播收尾和报告位置。同一上下文已读且未变化的通用文件不用每轮重读；每轮必须回读任务状态和新数据。

### 每次结束前的交接清单

公共环境写入根接续状态；下表中的账户、策略、场次、调度、台账与复盘写入本任务独立接续状态。工作区索引只链接实际文件。每项写“已验证 / 待完成 / 不适用”，不能以打勾代替证据。

| 交接项 | 必须留下的信息 |
|---|---|
| 目录 | 程序、客户工作区、运行配置与数据目录的真实绝对路径 |
| 阅读进度 | 已读流程、当前适用版本或核验时间、尚未读且下一步需要的文件 |
| 环境 | 服务地址、所属程序、浏览器连接状态、最后验证时间；不能写凭据 |
| 账户 | 名称、account_id、主计划，千川及罗盘各自的验证结果和缺口 |
| 策略与权限 | 当前策略文件、用户确认范围、实际模式和阻断项；个人技巧仅留客户文件 |
| 任务与场次 | 任务文件、任务状态文件、room_id、开播时间、session_key；未取得则待确认 |
| 调度 | 真实任务 ID、频率、停止条件、回读状态；未创建就明确未创建 |
| 决策留底 | 最近台账 round_id、回读结果、未落盘轮次及原幂等 ID、待补记录位置 |
| 复盘 | 本场报告路径、阶段或最终状态、数据截止时间及缺口；没有则不虚构 |
| 下一步 | 下一 Agent 应先读的文件、第一项具体动作、已问未答的问题与阻碍 |

接手 Agent 先读映射 → 公共部署状态 → 本会话账号任务的接续状态 → 当前策略 → 当前任务及任务状态 → 同任务最近决策记录，再核验服务、权限和实时场次。沿用真实调度，不重复建任务。完成本轮后更新同一份接续状态。

用户日常只需给出一份任务文件：`读取 <客户工作区内盯盘任务文件的绝对路径>，启动或接续盯盘。` 该文件集中保存本次个人规则和上述流程、策略、状态的实际路径；Agent 根据文件读取依赖，不要求用户每次粘贴长提示词。定时任务的唤醒提示则必须写“读取该文件，仅执行一轮，不重复创建调度”。

### 对客户的简短汇报格式

初始化结束：已完成｜当前可用｜尚缺及原因｜下一步。分别说明工作区、服务接入和盯盘调度，不能把“文件已建立”说成“已开始盯盘”。

日常轮次的汇报字段、频率与静默条件统一按[当前 Skill 的对话输出](../skills/qianchuan-ops/SKILL.md#对话输出)。浏览器统一控制器仅维护本场当前状态、比较基线和原未决，工作台读取摘要；不逐轮存档或另写重复决策台账。执行归属、未知提交和跨通道记录仍按各自契约核验；摘要展示不能证明广告或调度正在执行。

复盘按内置模板输出，结尾给客户可点击的报告路径。不能用聊天回复替代本机报告及原始操作回执。

### 什么叫初始化完成

分开报告三个结果：
1. 文档工作区已建立，换 Agent 能定位策略与任务。
2. 服务、浏览器和账户已真实验证；缺失或未在播明确标注。
3. 只有客户要求持续任务，且宿主返回了真实调度回执，才算循环盯盘已启动。

初始化不会自动获得投放权限。程序运行数据的位置使用 setup 返回的 QC_RUNTIME_CONFIG_ROOT、QC_RUNTIME_DATA_ROOT；不把它们与文档工作区混为一谈，不复制其他账户的 Cookie、Profile 或旧任务。

要模拟完全没有旧账户的新客户，按[全新客户验收](内测交付.md#全新客户验收)使用新解压通用包。清空文档工作区不会自动清空现有服务中的账户，不能把两者视为同一项测试。

## 账户接入与配置契约

打开本机工作台 `/v4`。无账户时自动进入“接入与配置”；已有账户可继续配置或新增账户。没有历史数据、不了解 ROI，都可以先完成账户接入。

用户操作与缺项问答统一见[用户引导](用户引导.md)。本节供 Agent 和开发者核对接入接口、保存事务及后续校准。

向导保存账户事实与任务偏好，mode 等旧字段仅为草稿兼容，不设置执行开关。日预算、场预算和测试损耗尚没有贯穿全部写入口的统一强制链路，Agent 须根据任务判断和核验，不能把记录偏好称为程序已强制执行。刷新 Cookie 和保存向导均保留既有账户策略。

### 共用入口

CLI 保留 `npm run setup`。HTTP、CLI 调用 `accountOnboarding` 的问题定义、验证和保存逻辑；没有另建后端，也不要求新用户安装 n8n 或 Cookie 中转服务。

| 入口 | 能力 |
|---|---|
| `GET /api/onboarding` | 首次状态、已有账户、浏览器登录说明、官方手册可用性 |
| `GET /api/onboarding?account_id=…` | 当前答案、缺口、下一组问题、草稿版本、平台观测、授权与只读预演结果 |
| `POST /api/onboarding` | `import`、`select`、`draft`、`rehearse`、`save` |
| `npm run setup` | 已有账户选择、分组问答、只读预演和确认保存；Agent 本机同步保留内部导入参数，不要求用户导出文件 |

HTTP 接入仅限本机同源访问；POST 必须是 JSON 且携带 `x-qc-onboarding: 1`。网页已处理此请求头，普通用户不用填写。

Agent 初次连接没有账户时，业务工具返回 `account_setup_required` 和本机接入地址。读取本机账户接入页面后按 `next_questions` 每次只问一个必要问题，复用 `revision` 保存草稿。不让用户写启动提示词；不重复索要已有答案；不把“请求的授权”说成“已生效权限”。

### 数据边界

- `platform_current` 是已核验计划的当前 ROI/出价、预算与口径；不是经营目标。
- `answers.target_roi` 与 `operating.roi_basis` 是用户经营目标；保本线单独保存为 `break_even_roi`、`break_even_roi_basis`。
- 未知数值保留 `null`，有效零预算保留 `0`。没有历史时不生成流速容量或素材推荐。
- 平台列表、余额、直播状态分别有读取时间和有效性；直播状态缺失是 `null`，不是下播。当前只有计划状态，尚未把全部追投和短期工具状态纳入接入预演。
- 首次账户身份只读验证必须成功；主计划缺失或冲突可先保存账户资料，但不能宣称主计划已核验。
- 预演十分钟后、草稿被修改或 Cookie 已变化，保存前需要重新预演。多入口版本冲突返回 `409`，不覆盖后来者的数据。

### 保存与恢复

默认以 `server-app` 为配置根目录；便携部署用现有 `QC_RUNTIME_CONFIG_ROOT` 指定其他目录，不依赖开发者电脑路径。

| 文件 | 内容 |
|---|---|
| `config.json` | 账户注册、独立 Cookie 文件名、账户级执行限制 |
| `account-profiles/<id>.json` | 经营目标、预算、授权意向、来源、用户确认时间、能力缺口 |
| `onboarding/<id>.json` | 分步草稿、版本、只读预演与观测；不存 Cookie 正文 |
| `scripts/qianchuan_cookie_<id>.txt` | 兼容现有读取模块的 Cookie header，只保存在本机 |

Cookie、配置和 Profile 使用同一恢复事务写入。失败恢复旧文件；进程崩溃后下次读取配置前恢复未完成事务。跨入口保存会检查文件版本。事务恢复文件可能包含之前的凭据，和 Cookie 一样属于私密运行资料，不能公开或提交。

Cookie 导出必须来自千川域；其他网站条目忽略。格式错误、过期登录项、账户不符、同名不同值或无法安全转换的路径 Cookie 会明确拒绝，不试着猜。在线验证只发读请求，不测试真实投放。

### Skill 与发布边界

`qianchuan-ops` 提供规则核验、通用分析方法及单独标注的课程经验参考，不包含账户默认阈值或初始化流程。Agent 充当投手时按[投手决策入口](../workspace/运行入口/投手决策.md)组织方法与经验，具体参数来自当前账户策略。项目入口负责自动引导；配置保存答案；Agent 判断；服务端约束与执行。官方资料先查 `QC_OFFICIAL_SKILL_DIR`，再查当前用户的 `.agents/.hanako/.codex/skills/qianchuan-ops`，找不到就标缺失。

本次不是完整商业化安装包：未部署、未重启、未启用客户自动投放。分发前必须排除真实配置、Cookie、Profile、草稿、恢复事务、历史库与抓包；`.gitignore` 不会自动移除已经跟踪的自用档案。

### 接入后的账户校准

接入完成不等于经营参数已校准。保留原有只读校准流程，但不把它设为新用户首次使用的门槛：

- 用当前账户页面与盘面核对身份、场次、主计划、数据时间和各 ROI 口径；冲突时列出来源，不自行选值。
- 按需读取最近 7～14 天可比数据，整理基础/追投/总流速容量、经营漏斗与渠道基线、样本门槛、时段和场次时长、素材与追投结构。每项带来源、更新时间、样本和缺口；漏斗转化率按 `0..100` 保存，`12.5` 表示 `12.5%`。未知渠道不猜标签。
- 主播、商品、价格机制、时段等可比条件须记录。财务保本线来自用户确认的成本口径，不能用历史 ROI 代替；无法校准的字段继续缺失。
- 向用户确认经营与财务边界、受保护对象、禁止恢复对象及执行授权。至少完成一场只读观察，核验累计、边际与直播起止后，才考虑将校准状态改为 `confirmed`；向导本身不自动执行这一步。
- 旧 `settlement_net` 迁移为 `platform_net_1h` 并保留迁移说明，不解释为最终结算。旧 Profile 缺少基线时可以读取，降低判断置信度，不填入虚构阈值。
- 商品、主计划、主播、时段或口径显著变化时重新校准。账户规则不写入官方 Skill，也不复制给其他账户。

将来补齐全部预算硬限制并验证后，再按用户确认逐级开放操作。当前新向导没有授权激活入口；`confirmed` 校准状态也不能绕过这个限制。
